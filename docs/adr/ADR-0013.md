# ADR-0013: 固定查询成员集、授权游标与投影候选读取

状态：Accepted  
日期：2026-10-08  
关联：ADR-0011、ADR-0012；不将 ADR-0004 的全部容量路线自动标为完成

## 背景

按业务 occurred_at 的实时游标会漏掉较晚接入但发生时间较早的事实。SQL ID、Kafka offset、
最大序号都不是固定证据快照。归档读取持有 Store.mu 会使远端等待阻塞其他接入。
浏览器将敏感搜索摘要作为查询字符串也不符合最小暴露边界。

## 决策

1. `GET /api/v1/events` 与新增 `POST /api/v1/events:query` 共享服务端鉴权、租户作用域、
   读自审计和固定成员集分页。浏览器使用 POST，筛选/搜索摘要/游标仅在 JSON body；
   URL 只携带非敏感 tenant selector。GET 保留兼容，但不应在 URL 使用敏感筛选。
   body 中未知的 tenant_id 不改变外层可信 scope；平台请求仍须显式选择租户。
2. 首次成功查询形成有序身份/流/序号/哈希/发生时间成员集，count 固定为成员数；
   以后到达/提交的事件只在新查询中出现。不是单事务跨后端的瞬间快照，不证明
   账本或当前投影完整，响应明确 `completeness=not_asserted`。
   既有时间线及 Snaplink all-tenant Console 保留原接口语义，不能据本决策称其固定。
3. HMAC 游标与成员集分别使用独立用途标签，绑定 tenant、subject、查询来源、所有
   筛选和规范化页大小。筛选指纹也使用 keyed HMAC，不在游标暴露 payload digest，
   不使用可枚举的无密钥敏感筛选摘要。每页重新鉴权和自审计，不将成员集当权限。
   旧、篡改、过期、缺失或作用域不一致的游标失败为 400；不静默重启实时分页。
4. 成员集是独立、可丢弃的运行元数据：文件模式 `query-snapshots/`、PostgreSQL
   `audit_query_snapshot`（迁移 008）。不复制 payload/密文/原始筛选，不写 control
   或不可变账本。有效期 15 分钟，最多 10000 个成员、4 MiB 编码、每租户 16 个
   活跃分页集；耗尽返回 429，不截断成功。PG 按租户事务锁统一跨副本预算；
   文件后端沿用单写者约束。创建时清理已过期运行元数据，绝不清理 WORM 对象。
5. 续页最多读取一页精确坐标，使用最新 committed receipt 和版本精确的 Schema。
   锁内只复制 catalog/hot anchor；外部 Get、认证内容及排序在锁外。整个操作共用
   既有 Store timeout，包含归档和自审计，保持 503 store_timeout 与 deadline 指标。
   坏/缺失证据不跳过、不计作正常空页。单事件读同样采用锁外按需取证。
6. `AUDIT_QUERY_CLICKHOUSE_DSN` 显式启用候选索引；不设置则使用参考账本查询。
   API 使用只读 schema/依赖探测，不自动创建/重建表。ClickHouse 在租户内逻辑
   event_id 去重，保留变体冲突；筛选值参数化，时间采用毫秒物理预筛加 Go 精确
   RFC3339Nano 比较，保持 1900–2299 年契约，不用 DateTime64(9) 的较窄时间域。
   全部候选坐标先与 committed receipts 核对；返回页从 Ledger/WORM 取证并认证，
   再核对发生时间及筛选，投影不能决定事实是否存在或直接输出受保护包。
   目的地失败/冲突不退回参考实时结果。已固定成员集续页不重读投影，因此目的地
   暂不可达不改变该结果集。配置/查询来源变化使旧游标失效，而不是跨来源套用。
7. 派生搜索摘要不存于 ClickHouse；包含 payload_field/digest 的查询明确走账本适配器，
   不把摘要传给 ClickHouse 或诊断。兼容跨格式比较、tenant/field 绑定及密文保护不变。
   参考初页仍可能扫描全部历史；v1 PostgreSQL 续页仍有旧快照物化成本。新候选
   查询/结果集有预算和超时，不声称所有历史读取、统计或生产规模成本已经解决。

## 后续认证演进

ADR-0030 将普通 ledger-reference 初次选择改为 receipt/map、精确 Schema/内容/链认证
之后才评估全部筛选，复用 Console 的 owned/锁外扫描；敏感条件从认证原值按自身格式
重算，新增普通加密 searchable 初页的 bound/legacy 互查，不再信任 sidecar。旧 helper
兼容限制仍保留测试，原成员/游标格式与旧保存集合不重选，Console 不新增匹配上限；
全历史物化/认证扫描成本仍在，不改本 ADR 的配额/TTL/来源/权限与完整性边界。

## 升级、回滚与验证

- v1/v2 PostgreSQL API 部署前应用 008；启动/readiness 缺表失败关闭。
  `-check-config` 仍无网络，不能证明迁移、依赖就绪或投影完整。
- 启用查询前先用 projector 初始化/重建新表并核对逐流前缀与账本头；新表缺失历史
  不能据 indexed/archived/broker 确认声称完整。API 使用只读查询角色，凭证由环境
  注入，不记录 DSN。该连接不赋予身份、审批或业务执行权限。
- 回滚保留 ledger/WORM/publications；运行成员集可过期或丢弃，只要求重新查询。
  不自动改变 ClickHouse TTL、归档保留期、Legal Hold 或删除不可变事实。
- 回归覆盖迟到事件、跨主体/租户/筛选拒绝、损坏/过期成员集、缺失选中证据、
  后端重启、文件预算、真实 PG 跨副本准入、ClickHouse 去重/冲突/纳秒边界与远期
  时间域；每批仍需完整质量门禁。基础设施、容量、容灾与正式合规验收独立记录。
