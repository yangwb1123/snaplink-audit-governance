# ADR-0037: 导出执行器尾部读取的本地保留与原子唤醒交接

状态：Accepted  
日期：2026-10-18  
关联：ADR-0014、ADR-0019、ADR-0021、ADR-0023、ADR-0024、ADR-0036

## 背景与有限范围

有限 dispatcher 的执行器原先在 runExport 返回后先删除 exportActive，再读取 control
决定是否唤醒下一轮。因此即使心跳已停止、终态已可见，执行器仍可能等待最后一次
Store 读取，而本地却同时显示零 active / 非 dispatching；删除与后续 wake 之间也有
空窗。按该状态观察退出的夹具可能提前 Close，不能把终态可见当作完整执行器退出。

本决策只修复这段进程内生命周期记账，不增加产品能力或 shutdown API。修前真实
Backend.Load 暂停确定性复现上述假空闲；这不证明旧 service 累计10m超时或原导出
running 的唯一根因。旧0014自验/独立失败及同源码最终完整通过均保留，不能互相抹消。

## 决策

1. 本地 reservation 保留至 runExport（含原 heartbeat stop/join）及最后一次有界
   ReadControl 都结束。该读取仍在 exportMu 外，沿用原 Store operation deadline、
   取消/错误与原读取次数，不新增等待、存储操作、远端 I/O 或忙重试。
2. 在同一个 exportMu 临界区删除 reservation，并在已知终态/目标已不存在时登记
   原有限后继 wake。共用 wakeExportsLocked：先增加 generation、必要时置 dispatching，
   再启动原 dispatcher；若已有 pass，沿用 generation 复查，不创建第二个 dispatcher。
   临界区不调用 Store/归档。这样无后续未登记读取或 wake 藏在本地 idle 观察之后。
3. 最后读取失败、取消、超时或仍为 pending/可续跑 running 时，只释放本地 reservation，
   不立即热重试；仍依赖原队列/worker 后续 pass。局部观察不能猜未知 Save 成功、改变
   终态或撤销已耐久事实。保留 selected/pages/sealed、lease/阶段 fencing、当前 Hold、
   必要读自审计、128/32 队列与 running2/tenant1 的共享 control CAS 权威。
4. 本地 reservation 现在可能短暂包含已完成/取消但尾部仍在途的任务，继续占原本地
   有限槽；不重新占用共享 durable running、不改跨副本准入或扩大物理停止保证。
   终态不是进程退出证明，心跳停止也不是最后一次 Store 读取完成；都不变为业务执行。
5. 原真实文件 TestExportMatchesQueryEventsOrder 在 cleanup 使用既有2秒观察护栏，
   等待 dispatcher 和完整 executor idle 后再由已有 cleanup 关闭 Store/移除文件；
   正常及早退均执行，超时仍报告失败，不伪造 join。原4个事件、查询/导出顺序/成员、
   AEAD与其余摘要回归、实际 Put/Get/Save/append/fsync、5秒终态等待与10m包上限均保持。

## 验证、兼容与限制

修前六种结局在实际最终 Backend.Load 入口都观察 active=0/dispatching=false；
修后矩阵另覆盖明确 Put 失败终态，检查 active 保留、锁未跨读持有、heartbeat join、
一次有限完成唤醒、错误/取消/实际 deadline 不热重试，以及原终态/租约/阶段/事实不变。
这些调度 oracle 的内存依赖不替代原文件测量或持久验收。取消场景还须确认原
CancelExport 的一次独立 wake，并在真实 Put 仍暂停时等该有限 pass 退出，才进入
尾读观察；不能把合法 active=1/dispatching=true 的并发当作假空闲。首次完整quality
曾因此夹具遗漏而失败（service 326.947s、取消子项0.01s，并非累计超时），原失败保留；
修正同步边界，原 active/dispatching/唤醒/状态断言及等待/deadline不放宽，重新完整验收。

独立 PG17 pools 与真实 FileStore 源/导出另验：真实终态提交后，在 heartbeat 退出
边界占住本测试专用单连接池，以 database/sql WaitCount 证明最后实际 SQL 读取在途，
而非睡眠猜测。另一个 pool 新增当前 Hold，尾读释放后不覆盖它或原证据/终态，下载
仍被当前 Hold 拒绝。单连接池只作测试同步，不新增生产池默认值。原回执精确索引、
文件重启与独立PG回归复核，不重交ADR-0033代码。

无新路径/字段/scope、SQL、topic、Proto方法、持久/密封格式或迁移。调用方仍须先停止
队列与外部 waker，再观察退出/关闭资源；这不是通用 Service.Close/Store 全方法 fencing、
任意后台任务收集或跨主机强停。文件单写者、备份/停写升级/回滚、未知对象与COMPLIANCE
边界不变。不改生产 deadline、认证、规则/阈值，不清历史/未知 temp/WORM/旧卷。

全 service race/JSON/逐测试及原导出阶段、专项/真实PG、完整quality/Web/security和随后
独立工程验收分别绑定源码留证。一次全量绿或总耗时变化不证明所有累计成本/历史running
根因闭环，不作磁盘唯一归因或容量SLO。M1/M2/M3整体仍Partial，M4/M5及整栈/Hosted
Login/容灾/正式合规独立待办；安全扫描非零仍阻塞发布，不以本ADR授予发布批准。
