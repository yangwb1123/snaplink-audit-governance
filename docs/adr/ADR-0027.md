# ADR-0027: 操作摘要的锁外认证读取与共享操作预算

状态：Accepted  
日期：2026-10-17  
关联：ADR-0002、ADR-0013、ADR-0015、ADR-0019、ADR-0025、ADR-0026

## 范围与背景

Service.Operation / GET /api/v1/operations/{operationId} 原通过 eventsFor 在 Store.Read
闭包内回读 WORM，慢源 Get 阻塞同 Store 的控制写、租约续期与所有者取消。旧热正文
可以在内容认证前参与 operation 筛选、时间/outcome 统计；仅复算引用 SourceDigest 的
归档链哈希不能替代重建内容认证。后续读事实追加又开始新的存储操作预算。

只改这一摘要服务和既有 HTTP 端点，复用 ADR-0025 的认证源。不改旧全量时间线、
replay/restore、Console、固定成员事件查询或导出执行阶段；审批/回放仍不执行业务。
后续 ADR-0028 再改造 operation replay 及其已有内部恢复委托的证据读取；旧全量/
aggregate replay、恢复整体流程仍未完成，不改变本 ADR 当时仅摘要的范围。

## 决策

1. 每个摘要服务调用先用 Store.WithOperation 建立一次原有 deadline，再由既有
   readTimelineEvidence / Store.Snapshot 捕获独立深副本。只有捕获/后端物化持有
   Store.mu；远端 Get、精确 Schema/内容/链认证、筛选和摘要聚合在锁外。捕获、
   取证、聚合与一次失败关闭读自审计共享原预算，不按对象或 append 重新计时。
   生产 timeout、调用方取消与 store_timeout/503 分类、计数不变。
2. 从目标租户 committed receipts 锚定，核对 map key 与正文 tenant/event 绑定。
   本租户 key 或正文错绑失败关闭，其他租户证据不 Get/认证；hot-only/journal
   不成为事实，v1/v2 兼容读取同样处理。使用精确 Schema ID/version/定义重建内容
   并核对 receipt/链哈希，再评估 operation 条件和 count/time/outcome，不能用
   损坏的谓词/统计字段将证据隐藏为空摘要/404。缺失精确版本不以最新版本替代；
   停用历史 Schema 不妨碍读取其精确版本。坏/缺证据拒绝整次摘要，不返回部分统计。
3. 保留原租户/权限边界：签名 tenant claim 权威，平台显式选择单租户，仍要求
   audit:operation:read；不获得 Console 的 tenantless/all-tenant 例外。空 operation
   仍先拒绝，无匹配仍 404，均不追加成功读事实。HTTP 在认证前设置 no-store，覆盖
   成功和全部错误；认证故障沿用固定脱敏错误，不输出原载荷、密文、搜索摘要或凭据。
4. 保留 live 摘要语义：event_count 是本次全部匹配数，first_at/last_at 是最早/
   最晚 occurred_at，outcomes 排序且去重。直接求 min/max，不为摘要再排序全部
   匹配事件。迟到/新提交可改变下次摘要；不是固定成员集或全历史完整性证明。
   不将旧全量时间线的 10000 条保护上限引入摘要，不新增截断成功；既有服务操作
   deadline 仍权威，10001 条语义回归不作为生产容量/吞吐保证。
5. actor-bearing 成功须 append-before-serve 恰好一个原 audit.event.read，保持
   tenant/actor、target_type=operation、target_id 与 detail=summary；内部空 actor
   保持零事实。Get/认证/聚合/追加失败或取消返回零摘要。追加已提交但回报未知、
   或追加成功后取消，仍不输出数据，不撤销尝试事实，也不将它视为字节交付证明。
6. 使用同一次捕获的证据与精确目录，不把后续 catalog 写混进本次认证；新调用重新
   捕获并认证。只追加独立读事实，绝不将捕获快照写回覆盖并发终态、租约、Hold、
   策略、计划/页/检查点。该观察点不是跨后端原子快照，摘要不替代导出当前 Hold、
   读自审计、owner/阶段 fencing 或共享队列 128/32、running 2/1 预算。

## 成本、兼容与未交付项

无新路径/scope/公开字段、topic、Proto 方法、SQL/密封格式或持久元数据，无需迁移。
认证收紧会拒绝以前可能被条件隐藏的坏证据或不可认证精确目录，须修复原证据/目录，
不能删历史、改写身份/版本或降低认证换成功。

仍物化历史、排序 receipt keys、认证扫描本租户全部 committed 证据并保留匹配事件；
摘要省掉后续事件排序不等于有界历史成本、恒定内存或容量 SLA。参考初页、旧全量/
replay/restore/兼容 helper、其余 Hold 成本及 ClickHouse facets/完整性仍分别待办。
M3 整体 Partial；selected/generating/sealed、租约/心跳、取消/关联新任务重试不重复
计功，最终整块密封/认证流式下载、M4/M5 和业务执行未在本切片交付。

## 验证与部署

先在实际暂停 Get 边界复现原 Store.mu 阻塞，以及热/归档 operation/outcome/time/
内容污染被隐藏或计入摘要。回归覆盖 receipt/精确 Schema 绑定、历史停用版本、保护
字段/大整数、hot-only/其他租户隔离、live count/min/max/owned outcomes、原 Load/Get/
append deadline、真实超时计数一次、取消、追加失败/未知结果和追加后取消零响应。
FileStore 源对象保持真实读写，独立 PG17 pools 在 Get 暂停时续期、取消并修改 Hold/
策略，读取不得覆盖已提交终态/control；HTTP 验证授权先于 Get、摘要形状、no-store
与固定错误。纯认证/预算矩阵使用隔离内存对象和实际 Store Save/append 边界，不要求
无关文件准备吞吐，也不据此声称崩溃持久性。

本轮新能力之前，原样完整 gate 再次发现查询锁 oracle 把无关 control/trail fsync 放进
5 秒调用护栏，以及 service 包在 chronology 准备 fsync 处超默认 10 分钟。仅将两个
纯查询 scope/tamper 夹具与锁 oracle 的 control/trail 使用生产内存后端，锁测试保留
真实 FileStore 源、原 5 秒上限，并补返回成员/读事实/并发 control 和所有 goroutine
退出断言。文件 restart/expiry、按坐标归档续页仍保留文件后端；新增 file/memory
逐字段证据与两页/读事实等价回归。没有放宽生产/测试 timeout、门禁或删除原断言；
修复后的完整 quality 退出 0 后才实现本摘要切片，原失败日志保留。

完整 quality、Web 与 security-scan 各自记录真实命令/源码绑定/退出码，组件或模型
自验不代替随后独立工程、整栈/Hosted Login、容量/容灾、合规或发布批准；安全扫描
非零继续阻塞发布。沿用既有完整备份、停写升级/回滚和旧 writer 字段保留要求，不清
WORM、未知对象、账本/journal/历史、旧卷，不变更留存/COMPLIANCE 或原终态。
