# ADR-0035: 既有恢复审批/拒绝的控制 CAS 重判

状态：Accepted  
日期：2026-10-18  
关联：ADR-0014、ADR-0017、ADR-0019、ADR-0020、ADR-0023、ADR-0028、ADR-0034

## 背景与有限范围

ApproveRestore / RejectRestore 仅保存治理决定，却走通用 Store.Update。文件 v2 替换
未变的 hot/cold 证据文件；PG v2 的整快照兼容路径在实际 Save 冲突后可能复用旧
working copy，覆盖先提交的审批/拒绝、并发取消/租约撤销/阶段、Hold和策略。旧返回值
还可能在 Save 失败、结果未知或重试被拒绝时携带未确认的决定。

本决策只修复这两条既有决策的持久提交，不新增恢复能力或业务协议。局部写放大与
控制覆盖可确定性复现，但不是历史 service 累计10m超时或原导出 running 的唯一根因
证明。保留旧0014的真实失败及同源码最终完整通过，不用后来的绿抹去前者。

## 决策

1. transitionRestore 显式使用 UpdateControl；每次实际 Save 冲突后，在新鲜 control
   上重新运行原记录/tenant、pending 状态与职责分离检查，不把之前物化的 working
   copy 保存回去。保持 NotFound→Conflict→Forbidden（404→409→403）优先级：跨租户/
   缺失仍404，已有决定仍409，自我决定仍403，不从其他租户或旧状态推断授权。
2. 首个耐久审批/拒绝的 actor/time 保持；后来的相同或相反决定均409、零 Save/零
   重复事实，不改为幂等成功。合法 pending→approved/rejected 与原一次对应决定事实
   同 CAS 提交；冲突重跑只提交最后真正通过检查的一次变更，失败不留下半个决定。
3. 不物化/重写 v2 hot/cold，不读取或写入 WORM，不保存旧 control 覆盖较新的导出
   终态、lease、plan/chunks/checkpoint、其他恢复决定、Hold或策略。取消不能因无关
   审批被撤销，旧 owner 不能恢复运行权或发布迟到对象；原128/32、running2/1、当前
   Hold、必要读自审计与 owner/阶段 fencing 继续各自权威。
4. 一次原决策 operation deadline、有限冲突重试/退避与取消/超时分类不变，不按
   attempt 重启预算。任何错误返回零 RestoreRun，不暴露之前 attempt 准备的成功值。
   Save 真正提交后却回报错误/取消仍是未知结果，已耐久决定/事实不撤销；须只读核对，
   不新增自动重发、回滚或请求幂等承诺。已知成功的原持久化语义保持。
5. 不执行补偿、恢复或其他业务 API。审批仍不是执行；不新增正式 scope、持久证据/
   业务版本计划、有效期或独立业务执行回执。CreateRestore/GetRestore、其原内部空
   actor 读取策略及创建的分离操作预算不在本切片修改范围，不能把决策的一次预算
   冒充整个创建工作流的一次预算或原子证据快照。

## 兼容、验证与限制

无新字段、路径、scope、topic、Proto方法、SQL或持久/密封格式，无需迁移；原授权与
HTTP错误分类保持。真正竞争后，现在保留并观察首个决定并拒绝旧观察，不能错误成功
覆盖它。通用Store.Update、创建/读取与旧v1兼容路径/共享control历史成本未整体改造。
M1完整语义矩阵、M2历史成本与容量、M3整体及M4/M5仍未完成，不因此扩产品范围。

回归先在原生产源码上复现：真实两租户文件的四个hot/cold inode被替换，实际PG17
独立pools的Save冲突后首个决定/并发取消/lease/selected或sealed阶段被覆盖。文件
回归保留原字节/版本、真实归档与选中计划、未知temp、重启与当前Hold门禁；决策零
源Get/Put。PG用实际control行锁与pg_blocking_pids同步Save，覆盖相同/相反首个决定、
当前作用域/职责变化、目标缺失及无关control，核对真实版本增量、事实和晚owner零
发布。测试捕获的可选空map须与真实loader一致归一化，不把nil/空map表示差异当作
丢失阶段；非空原阶段必须来自真实认证/提交，不能用合成无效引用代替。

实际Save失败/提交但结果未知、取消/实际Save deadline、原预算与有限重试另验，保留
所有修前与夹具接线失败。定向race/PG不是完整quality替代；完整自验与随后独立工程
验收分别绑定源码留证，security-scan非零继续阻塞发布。文件同步helper和生产deadline
不变，少写无关文件不是时延SLO、全部累计耗时根因、容灾或正式合规保证。

沿用完整control（含任务/关联/lease/计划/页/检查点/恢复决定）、ledger/hot/journal/
确认/原密钥备份，停写升级/回滚并核对旧writer字段保存能力；不混跑会覆盖字段的旧
writer，不将终态退回pending，不清理未知对象、原历史或旧卷，不缩短COMPLIANCE。
