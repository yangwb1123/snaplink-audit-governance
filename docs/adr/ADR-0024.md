# ADR-0024: 固定成员导出的逐页生成检查点

状态：Accepted  
日期：2026-10-16  
关联：ADR-0013、ADR-0014、ADR-0019、ADR-0020、ADR-0021、ADR-0022、ADR-0023

## 范围

在 selected 与最终 sealed 阶段之间持久保存**实际已生成 JSONL 页的认证对象引用**。
接管不会重新读取/编码/密封已提交页的原事件，而是认证复用原页，只生成剩余成员。
这不是重选整块、心跳、关联新任务 retry、终态重排队或业务执行。
最终仍合并全部页并按现有 export:v2 格式整体密封/下载；**不是流式大文件下载、
恒定内存或 M3 全项交付**。首次选择仍扫描历史，当前 Hold 仍可能扫描当前历史。

## 模型、版本与配额

1. 新选择超过 100 个成员时使用 `export_plans.version=2`；`format_version=1` 仍表示
   现有最终 JSONL/export:v2 格式。每页固定最多 100 个有序成员，只有最后一页可不足。
   新的单页任务和已保留的 v1 计划继续原整块路径，合法历史 v1 计划不被自动改写。
   已完成/失败/取消任务绝不转回 pending/running，也不转换其密封格式。
2. v2 计划沿用原有完整任务 HMAC、有序原账本坐标/发生时间、精确 Schema ID/version/
   定义 HMAC，新增 `chunks` 有序连续前缀：每项仅有 First/Count、seal_version=2、
   不透明对象引用、密封/JSONL SHA-256 和时间。没有载荷、密文、原始筛选/搜索摘要或
   owner 副本；不进入公共 DTO、hot、事实详情或日志。最多 100 页，仍在 10000 成员/
   **4 MiB 总元数据**内；新 v2 选择在同一 4 MiB 内为每个可能页预留 1 KiB 引用空间。
3. 沿用同一个 control CAS 的队列 128/tenant32、running2/tenant1；进度只能存在于
   原 running 槽，保存每页也复核运行预算，不增加每页/跨副本执行器或租约。
   接管仍须合法原 lease 到期、新随机 owner、保留首次 started_at，不使用 15 分钟
   查询 cursor。计划 HMAC 与当前 owner/CAS 同时约束进度，不能跳页、回退或分叉。
4. 未知版本/格式、坏 HMAC、缺口/重复/错误范围、跨任务路径、未来/倒序时间、预算
   或 Schema 漂移均失败关闭，保留未知现场，不清空计划换启动或重选另一组成员。

## 页密封与执行

- 稳定 generation HMAC 绑定整个不可变计划（仅排除可变 chunks 和计划签名），用途
  与 scope/Schema/计划签名独立。页 AEAD 又独立绑定 generation、序号、First/Count、
  seal version 及不透明对象路径；路径含当前 owner 的哈希，不保存/泄露原 owner。
  跨 tenant/job/计划/格式/范围/对象交换均不能解开，拒绝 legacy export:v1 页降级。
- 每个未生成页从其原成员坐标读取最新 committed receipt/hot/WORM，认证精确 Schema、
  内容/链和发生时间，然后剥离搜索 sidecar、规范编码 JSONL、独立 AEAD 密封并 Put。
  元数据不是新事实源，不能从生成页为缺失/损坏的 ledger 创造 receipt。
- 每页先认证判定原查询的**当前** Hold（包括迟到事实，不改变固定输出成员），失败
  关闭内部 governance-worker 读自审计；Put 前复核计划/Schema/owner/Hold 集。
  Put 成功后同一次 control CAS 追加页引用与一次 `export.progressed`
  （`stage=generating version=1 pages=N`），再次复核精确未过期 owner、原计划 MAC、
  最新 Schema、共享运行预算与未变的当前 Hold 集。未知 Save 立即停止，不推进本地
  claim、输出路径或继续下一页；随后只以实际持久记录判断已提交前缀。
- 每页是一次既有 Store operation deadline：本页源读、Hold、读自审计、加密、Put
  和 Save 共享上限，不按对象重启；Put 还继承原 30 秒上限的较小值。原生产超时不
  改变。锁内只捕获/复核自有结构，远端 Get/Put 和认证锁外；慢页不阻塞续期/取消。
  明确 Put 错误沿用失败终态语义；取消/超时/过期仍须通过原 owner/计划 fencing，
  无法提交终态时保留实际已提交前缀，不把未知远端结果视作回滚。

## 接管与最终提交

1. 接管先验证完整计划、当前 Schema 和原成员最新账本坐标，重查当前 Hold 并失败
   关闭读自审计。只 Get 计划明确引用的已提交页，逐页核对精确密封摘要、页 AEAD、
   JSONL 摘要和有序身份/发生时间/Schema 版本，最后重查 owner/计划/Hold 集。
   该前缀验证共用一次既有 deadline；不从未知旧对象/key/临时文件猜进度。
2. 已提交页缺失、不可用、损坏、顺序/身份/绑定不符时保留计划、拒绝继续和发布，
   **不重读源事件来再生成已提交页**。原证据/密钥/目录修复后等待正常租约接管，
   或由已知所有者取消。当前 Hold 匹配则原子 failed + export.blocked，并清合法
   活跃运行元数据；原页和历史事实不删。详情/下载仍独立执行 ADR-0022 门禁。
3. 仅在全部页已提交、合并 JSONL 精确匹配原计划后生成最终整块对象；Put 前及最终
   sealed Save 复核计划/当前 Schema/owner，sealed Save 原子消费整个计划/进度。
   之后仍走 ADR-0021 原对象认证、最新账本坐标、当前 Hold/自审计和终态 CAS；
   正常完成/失败/取消只清合法活跃元数据，终态不回退，retry 不继承旧页。
4. 页 Put 后、进度 Save 前断电/未知结果可能留下无引用不可变对象。新 owner 只为
   未提交页生成不同 attempt key，不盲重放/读取未知旧 key，不删除它、不承诺一次 Put。
   旧 owner 的迟到 Put 同样可以留下孤立对象，但不能追加/覆盖新前缀或发布输出。
   最终整块密封/Put 不是本切片的细粒度检查点；该阶段尚未提交 sealed 时可重做。

## 部署、成本与验收

无新 REST 路径/scope/公开字段、Kafka topic、gRPC 方法、SQL 表或最终密封格式。
API/worker/所有 control writer 必须配套停写升级；旧 v1 plan writer 不认识 chunks/
v2，不能混跑、回写丢字段或清理计划。完整 control（任务/关联/leases/plans/chunks/
checkpoints）、ledger/hot/journal/确认与原密钥一起备份；页对象与最终对象均保留，
无自动 GC/删除/COMPLIANCE 缩短。回滚先停领取/写入、核对字段保存能力和未知远端
结果，不手改 owner/终态或从 running=0 推断外部 I/O 已停止。文件仍单写者。

首次选择、Hold/共享 control 克隆/CAS、页前缀认证和最终合并/密封仍有历史/内存成本；
每页是身份数有界，不是独立字节容量 SLA，S3 版本级 Hold/历史密钥需另行评审。
生产容量、容灾、整栈/Hosted Login、正式 WORM、安全发布和业务执行仍独立验收。
回归覆盖真实页 Put/Get/Save/append、未知提交、文件重启超过 cursor TTL、迟到成员/
Hold、认证/版本/范围/Schema 污染、读自审计、deadline、续期/取消/换主与独立 PG
pools 的共享 CAS/预算/tenant delta；完整 quality/Web/安全扫描分别保留真实结果。
