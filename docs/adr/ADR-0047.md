# ADR-0047: 既有租户/Schema 目录的控制面读取与单次预算

状态：Accepted（控制器已审查并接受此局部读取决策，不预授工程或发布通过）  
日期：2026-10-30  
关联：ADR-0002、ADR-0017、ADR-0040、ADR-0043、ADR-0044、ADR-0046

## 修前证据与范围

ListTenants / ListSchemas 只观察 control 目录，原实现却通过 Store.Read 物化所有
租户 hot/cold，且排序后没有取消复核。先新增独立的实际 Backend.Load 计数 oracle，
保持生产 service.go 与种子 SHA256 相同，再执行 TestCatalogControl：两列表在预取消
以及 Load 携有效快照返回时迟取消、真实 operation deadline、更早 caller deadline
四种情况下仍分别输出 2/3 项、err=nil；预取消仍 Load 一次，到期没有分类/计数。
原 Load 错误（含同时返回有效快照）则原样传播、零列表，不能将其写成修前失败。

独立真实 v2 文件夹具使用两租户、真实管理 API、原归档 Put/淘汰及逐次真实摄入/
Save/ledger append/fsync，不借 v1 oracle 冒充 v2 证明。同一 4498 字节 control，
邻居 1→32 个 hot 事件、2→33 份当前 receipt，新加分配观察中两列表各由约324增至
4277 次/调用（各4次调用，含 warmup）；此为局部工作集证据，不是吞吐或 wall SLA。
原文件/性能测试、样本、阈值、测量文件系统、5秒等待、10m包上限与生产deadline不动。

私有修前记录位于实施 evidence/A-catalog-control 的 red-catalog-corrected.log；
初次 red-catalog.log 也保留。初次新 oracle 错将调用前时间+timeout 当作上界，导致
成功/原错误分支额外失败；只将新 oracle 的比较点修成实际 Load 入口时间后，保持
生产源码未变再次记录。更正后的失败仅为撤回输出与 v2 无关证据分配增长，不掩盖
初次测试自身问题，也不将这些局部事实归为旧累计10m/running失败的唯一根因。

## 已接受的最小决策

1. 仅将两列表的读取改为现有 ReadControl；各在 Store 闭包外使用一次 WithOperation，
   覆盖 control 深副本捕获、原筛选/排序及最后的 opCtx.Err 复核。嵌套读取/v1回退
   继承同一预算；Load 不重试、不重新计时。任一读取/克隆/取消/超时失败返回 nil
   列表，保留原错误以及一次 deadline 分类/计数；预取消不 Load。
2. ListTenants 仍返回整个目录、按 ID 升序，不将 service 层变成租户 token 的过滤器。
   原 HTTP 平台权限保持；ListSchemas 保留 requireTenantScope、精确 TenantID
   过滤、SchemaID/version 升序，包含停用和历史版本，不新增当前 tenant 存在检查。
   HTTP 原签名租户/平台显式选择、权限、错误包及缓存行为不改。
3. 原字段与可空语义保持：成功无匹配仍为 nil 列表；Schema 四组 optional 字段列表
   沿用原克隆对 nil/空的省略语义，不改成非空 []。control 深副本承担四组切片的
   双向独占与重复读取独立；每次观察当前 control，不加缓存或额外单项读取。
4. 不 Save 捕获快照、不写 control/hot/cold、不追加任何新读事实、不 Get/Put WORM。
   保留这两个元数据列表原静默读策略，不削弱事件/回执等必要读自审计。目录观察
   不是内容/链认证、当前 Hold 放行、投影确认、完整性证明或业务执行/恢复回执。
   原控制 CAS、共享预算、owner/lease/阶段 fencing、终态不回退与审批非执行均不变。

## 治理 worker 的既有撤回协议

控制器首次完整 quality 在此实现上发现三个旧 worker 取消回归：公共 ListTenants 的
预取消拒绝使 runEvaluatePass 提前返回，破坏了其已固定的“首个在途租户尝试完整
步骤、再在租户间 abort”协议。失败原样保留，不能弱化公共目录读取或删旧断言。
worker 改用私有 governancePassTenants：直接 ReadControl 并按 ID 排序，保持原调用
的取消/更早 deadline 和真实 backend 错误；不 detach、重试或伪造目录。只有 backend
仍返回合法目录时才走原首租户序列；真正拒绝取消的 backend 仍失败退出。它不暴露为
HTTP/service 公共旁路，不更改恢复、租约、事实或留存操作自身的取消门禁，v2 仍只捕获
control。此处刻意不继承公共 WithOperation 的预取消/排序后拒绝；模式与 ADR-0044
的内部留存评估和公共配置读取分离一致。新独立回归核对公共预取消零 Load、私有路径
原 context/排序/独占、真实 Load 错误传播及零写入；原三个 worker 测试原样保留。

  缺注册但有 Schema、scope 拒绝、空结果 nil 以及四组切片的双向变异/重复读取/
  新 control 可见性。v1 Load oracle 核对原错误、预取消零 Load、迟取消/实际到期/
  更早 caller 到期、零列表、零 Save/LoadForUpdate/append/WORM 与单次计数。
- 独立 v2 夹具核对固定 control、两份 hot/两份 cold 的字节/inode/版本、原完整
  Snapshot、原管理与读事实、未知 control temp 保留及关闭重启；测量仅增加邻居
  hot/cold，不改变 control。它只验证本局部工作集与静默观察，不替代实际 PG 的
  独立 pools/证据表锁验证或全历史完整性、耐久/容量验收。
- 修后 TestCatalogControl 与指定既有 HTTP 四组租户/平台矩阵各一次命令退出0；

  GOMAXPROCS=2、-timeout 10m、-count=1，日志另绑实施源码留证。

  依赖/生成代码。
