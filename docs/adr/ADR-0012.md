# ADR-0012: 当前目的地投影确认、流前缀与账本重建

状态：Accepted  
日期：2026-10-07  
关联：ADR-0011、ADR-0004（Draft 生产查询路线，不因本决策自动视为已完成）

## 背景

Kafka 交付确认、回执 indexed、扫描位置和 ClickHouse 最大序号都不能证明查询投影完整。
旧 ReplacingMergeTree 排序键不能保留同一事件的不同投影变体；异步合并前物理 count 会重复。
Kafka 保留期耗尽或目的地重建后，需要从已提交事实重新生成投影，而不改业务状态。

## 决策

1. 新表 `audit_projection_events` 保存完整受保护事件包和其 SHA-256 摘要，保留密文，
   深拷贝后递归移除 payload/changed_fields 的派生搜索摘要，不在此边界解密。
   tenant/stream/sequence/event_id/hash/envelope_digest 均进入排序键，合并仅消除相同变体；
   不同变体不会被「最新值」掩盖。旧 `audit_events` 暂作兼容镜像，不作确认来源。
2. projector 强制 `async_insert=0`、`wait_for_async_insert=1`；新表启用
   `fsync_after_insert`/`fsync_part_directory`。同步写新表成功后方可确认消费成功。
   旧表成功、新表失败仍返回失败；重试允许重复，逻辑计数按 tenant/event 去重，存在
   不同坐标/内容变体则失败关闭。同步写是当前部署的投影持久边界，不是跨地域容灾承诺。
3. `Confirmed` 在**当前目的地表**按 tenant/event 读取并校验 stream/sequence/hash 与唯一
   envelope 变体。缺行是未知，冲突是错误；不得借用旧目的地、broker 确认或 receipt 状态。
   只证明已知账本坐标在当前投影可用，不由投影决定事实是否存在。
4. `Watermark` 为一个 tenant/stream 的当前已观察连续哈希前缀，从序号 1 的空 prev_hash
   开始，去除重复后逐序验证。缺号返回已验证前缀与 gap；变体或相邻链断裂失败关闭。
   单次查询/流式验证有共享 10s 上限，失败不能返回半个成功水位。Go 不物化全历史，
   但 ClickHouse 聚合/排序的规模成本仍须容量验收。它不是全租户水位、Kafka offset、
   不可变查询快照或全量完整证明，也不永久缓存为单调真相。
5. `audit-projector rebuild` 直接调用有界 committed-cold 分页，读取最新回执与精确 Schema，
   锁外获取归档，在整页共享 deadline 内重建/认证内容及链哈希后写当前目的地。
   不发布 Kafka、不重置消费者组、不删除表、不修改回执/Outbox/审批，不执行业务恢复。
   缺失/损坏证据不写入、统计失败；目的地/取消/超时失败不推进页位置，重复写入安全。
6. 每轮捕获有限扫描终点，默认两次从零开始的 sweep。SQL ID 不代表提交顺序，任意有限
   sweep 都不能保证捕获在其后才提交的低 ID；退出记录明确 completeness=not_asserted。
   关闭写入并完成源端一致性核对，或持续重复扫描并逐流比对账本头，才可作迁移验收。
   v1 PostgreSQL 仍物化旧快照；规模化读取必须先完成 v2 cutover。

## 运维与边界

- 重建进程使用账本路径/数据库的既有锁与配置；文件后端须停 API/worker，不能多写者共享。
  要求显式单租户和已存在账本，不自动创建 tenant、source 或 Schema。
- 密钥、S3/Vault 配置由环境传入，遵守既有独立密钥、TLS、COMPLIANCE 门禁；远端错误、
  DSN、归档内容与凭证不进入重建/检查命令日志。生产权限由运维凭据及数据库/对象 ACL 管控。
- 默认新表为空；旧镜像中的历史不会被伪造为已确认。用账本重建或 ledgered feed 重驱补齐。
  回滚可忽略新表，但旧计数/水位/新表不可因此宣称完整。表的迁移、TTL、备份及删除均为
  运维控制操作，工具不自动执行；当前实现不提供恶意 DBA 场景的独立投影认证。
- 查询 API 尚未改为 ClickHouse；固定快照/授权游标、敏感条件检索及全租户进度摘要仍是
  后续工作，不把本批基础设施作为 ADR-0004 或 M2 全体完成。
