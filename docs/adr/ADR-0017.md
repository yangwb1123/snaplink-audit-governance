# ADR-0017: 文件数据的描述符相对 I/O 与私有创建权限

状态：Accepted  
日期：2026-10-12  
关联：ADR-0003、ADR-0011、ADR-0013、ADR-0015

## 背景

文件模式的账本、控制面与自审计仍使用部分路径字符串 I/O 和 0640 创建权限。
词法租户编码不能阻止祖先目录或临时文件被替换为符号链接；直接 O_TRUNC 固定
`.tmp` 还可能覆盖不属于当前操作的残留。文件系统攻击面必须独立于 API 租户鉴权
处理，不能靠关闭扫描或迁移到空账本解决。

## 决策

1. Linux 文件数据通过 `internal/fsutil` 的 `OpenDataDir` 逐组件以 directory fd 与
   O_NOFOLLOW 打开所有祖先；文件只接受一个 basename，使用 openat/O_NOFOLLOW/
   O_NONBLOCK。打开后检查 regular、单链接 inode，先验证再截断，FIFO、设备、
   目录、符号链接和硬链接不能成为数据文件。其他平台失败关闭，不退回不安全路径 I/O。
2. 控制面、hot、ledger、发布确认、固定查询元数据、锁和自审计的新文件使用 0600，
   新目录使用 0700。读取旧 0640/0750 数据不自动 chmod；已存在账本的追加也不批量
   改权限。原子重写得到新的 0600 inode，备份与共享 UID/ACL 部署必须据此评审。
3. 原子写在同一 pinned parent 下以 O_EXCL 创建固定 `.tmp`，写入完整字节、文件
   fsync、close、renameat，再同步实际父目录和完整祖先链。原子写与 ledger append
   通过同一 helper 对捕获父目录执行一次实际 fsync，不再随后重复 fsync 同一父目录；
   仍按原顺序同步全部所需祖先，不缓存/跳过本次链。默认路径保留安全重新打开/关闭
   检查并核对父目录 inode；替换为 symlink 或其他真实目录均失败关闭。测试 hook 仍
   观察完整 leaf-to-root 链且不能替代实际捕获父目录的同步。仅清理本次成功创建的
   temp；已存在的 temp 无论文件、目录或链接均拒绝，不截断、不删除、不推断其计划。
   不改变租户命名、目录布局、JSON/JSONL、序号、链、签名或恢复 journal 内容。
4. `ErrDataDirectorySync` 区分 rename 后耐久边界失败与此前失败。兼容 fileBackend
   Save 保持旧的内存不发布/尽力恢复旧快照行为；hot/cold 与自审计保留自身已提交或
   结果未知的错误语义，不能把返回错误解释为磁盘撤销。恢复仍按 ADR-0015 的原计划
   和证据认证，不从任意临时文件推断 committed truth。
5. 文件查询分页元数据的扫描、读取和过期 unlink 绑定捕获的目录 fd，读取始终有
   4 MiB 上限。链接目录不可成为回收范围；只删除既有合法、已过期成员集文件，
   不能触及账本/WORM，不能改变 TTL、Hold 或 COMPLIANCE。
6. 既有进程生命周期 flock、单写者、Store deadline、取消、自审计、至少一次交付、
   授权游标和身份绑定保持。文件 API/worker 不共占同一路径，多副本继续使用 PG。

## 信任边界与限制

- 服务数据目录及其所有权/挂载由运维负责。描述符防符号链接重定向，**不防恶意
  mount/特权主机管理员、真实目录搬迁、全盘改写或签名密钥泄露**；不能据此声明
  本地 WORM 具备正式合规保全。数据目录不得依赖 symlink，须用真实目录/受控挂载。
- 不在本决策中把同一策略用于 Kubernetes symlink secret/certificate mounts；TLS
  配置读取和 DLQ state 独立策略见后续 ADR-0018，不把已处理的 store 文件算作全部。
- 旧组读权限、备份工具、服务 UID 和 ACL 须单独核对。新权限不能撤回已泄露数据；
  本版本不自动遍历 chmod、删除历史、清空账本或重新签名。

## 升级、备份与回滚

- 升级前停写并核对数据目录所有者、真实路径、硬/软链接、未完成 journal 和 `.tmp`。
  有未知 temp 时保留其原字节及元数据，人工核对原计划和冷证据，不能用删除换启动/
  写成功；hot/ledger 临时残留仍由既有 v2 校验拒绝，控制面临时残留阻止后续覆盖。
- control、tenants、ledger、未完成 journal、发布确认和密钥一起备份；备份身份必须
  有显式读取新 0600/0700 的权限。不能因为组读失效而启动另一份空账本。
- 回滚前停写，用当前版本完成已知 journal 恢复及 cold 核对，保存残留和证据。
  旧版本可能重新创建 0640 文件或截断旧 temp，不是安全恢复/权限策略；按受控运维
  流程处理，禁止两个文件写者重叠。

## 实现与验证

- `internal/fsutil/secure_file*.go`；`internal/store` 的 split、control、ledger、trail、
  publication、query snapshot 和 state lock 使用该安全边界，无 SQL/线面迁移。
- `secure_file_linux_test.go`：祖先/叶链接、硬链接、FIFO/目录、截断前验证、未知
  temp 保留、捕获 fd 后真实父目录替换、basename 拒绝、私有创建与完整 fsync 链。
- `secure_sync_linux_test.go`：实际目录 fsync 的确定性计数（原重复为 2，修后为 1）、
  全部祖先顺序/逐边界失败即停、真实已关闭 fd 不可被 hook 旁路、父路径被替换拒绝，
  以及 rename 后失败仍保留完整已发布 inode/结果未知，后续写重新建立耐久边界。
  原 5 秒导出等待、10 分钟测试包上限、操作 deadline、样本/并发/退出断言不变；
  同步次数减少不是磁盘时延上限或旧失败唯一根因证明，累计文件 I/O 风险仍须全量核对。
- 摄入归档的原 5 秒上限只计实际 Put 进入至 context Done，不把前后真实文件提交
  混入该计时。`archive_put_measurement_test.go` 在真实第二次 ledger append 暂停1.25s，
  先复现旧整次 Ingest oracle 错误（Put约5s、总计超过原6s上界），再保留原
  -500ms/+1s 容差改用真实 Put 边界；精确 deadline/调用次数/DeadlineExceeded 和
  indexed/非archived 断言、原文件后端及重启核对均保留。不是提高生产 timeout、
  迁移内存或取消事实持久化，整次接入 SLA/累计包耗时仍独立验收。
- `file_security_linux_test.go`：启动失败关闭、失败保存不发布、旧 ledger 权限不变、
  各类新文件 0600、查询元数据回收不越界。既有恢复/发布/自审计/归档回归继续保留。
- 正常 worker 启动的 SIGINT/SIGTERM 处理须在打开状态存储前注册：文件锁已可被
  supervisor 观察时，归档就绪预检可能仍未完成，持锁不是启动就绪。启动 Ready
  继承进程取消且保留原 5 秒上限；取消后不启动治理 pass，正常 Close 释放锁，
  不伪造归档/导出完成、重置终态或清理证据。无取消的 Ready 失败仍非零退出。
  真实启动 bucket HEAD 阻塞回归验证信号取消、退出、锁释放及原回执不变；文件锁
  challenger 的失败和 holder 的正常退出继续分别断言，不用延迟发送信号掩盖窗口。
- API drain 进程回归在启动被测二进制前，通过真实认证 gRPC 完成原事件的实际文件/
  归档提交并关闭原 writer；被测进程仍以原 1 秒 store/drain 配置认证同一原请求，
  返回精确匹配 hash/stream/status 的 duplicate 回执后才发送 SIGTERM。原长寿命
  JWT/无 timer 空闲流、无空闲流对照、退出上限、文件锁释放与单份原回执断言保留。
  新增实际归档 Put 暂停、准备未完成仍持锁/不返回、恢复后原字节取证回归；新摄入
  在途提交/未知结果的其他回归不被替换。此分离只消除准备 fsync 的隐含 1 秒要求，
  不改生产 timeout/认证/持久化、扩大重试或把 duplicate 当新提交/业务执行。
- 新摄入强停回归的旧 mutex 门实际会阻塞预检，不能证明已进入提交；其放行后的
  无关全快照 Save 还会与读取竞争。进一步在真实 hot 文件已提交后的 cold append
  边界暂停，原锁夹具的一次实际全文件 Save 移至准备期且核对逻辑状态/事实等价，
  实际摄入的原文件/ledger fsync 不变。保留 10s store、200ms 在途观察、50ms drain、
  无强停对照、唯一事件/回执和相同原请求 duplicate 重试断言。原 15s 收敛护栏一次
  覆盖 detached handler 退出与回执只读观察，不能用 transport EOF 推断 handler 已退；
  早退也释放并 join 自有 handler/listener。真实三文件 inode 对照证明旧准备 Save 没
  被内存替换或删同步。这不是既有 idle-stream 进程准备补丁的重交，也不宣称旧
  running/累计耗时的唯一根因闭环或放宽未知提交/生产 deadline。
- 跨进程锁夹具在启动 holder 前完成真实控制域/目录准备，仍以实际 flock 及精确
  当前 holder PID 同步、保留原 10s 信号后退出上限，结束后重开原文件核对域及零
  事件/回执/导出；不把旧准备 PID 当就绪，不延迟到业务就绪才发送信号。gRPC 新
  文件域的相同三个真实管理 API 可在隔离准备区产生目录/原事实，再一次 Update
  合入自有字段（保留其他 control、空 hot/cold 文件及重启可读性）；后续摄入仍用
  原文件 Save/append/fsync，注入故障/CAS 夹具保留原分次管理 Save。HTTP 归档 Get
  超时回归保持同一真实文件状态及原 150ms 读预算，只在实际摄入耐久、准备 HTTP
  handler 全部退出并重开原文件后启用短预算；原超时/503/脱敏/指标断言不变。
- 文件热冷容量的字节斜率回归不测串行归档准备吞吐：仍保留 100/1000/5000 个
  4096-byte 及 100 个 8192-byte 真实对象、原 metadata/阈值和 Walk/stat 测量，仅以
  至多 16 个独立 FileStore handle 写互斥 key 分区。每次 Put 仍经过原文件及完整目录链
  fsync；先 Ready、全部 writer 真正退出后用新 handle 逐 key Get 核对原字节再测量，
  小样本串行/并发测量必须一致。失败取消并 join 在途 Put，不把它当物理回滚。
  此测试准备调整不改生产同步路径/超时、不用 tmpfs 或内存替代测量，也不证明
  掉电耐久性、共享账本多写者或容量 SLA；原真实文件安全/重启/同步失败及独立 PG
  边界继续保留，不能用内存调度/认证 oracle 取代。
- 本机 quality、静态扫描与定向 race 分别记录；不替代真实 PG/Kafka/WORM、整栈、
  容灾、生产容量、正式安全发布或 M4/M5 业务协议验收。
