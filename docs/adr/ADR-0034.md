# ADR-0034: 既有 Legal Hold 控制写的 CAS 重判与零证据重写

状态：Accepted  
日期：2026-10-18  
关联：ADR-0014、ADR-0017、ADR-0019、ADR-0020、ADR-0022、ADR-0029

## 背景与范围

CreateLegalHold / ReleaseLegalHold 仅修改 control，却走通用 Store.Update。文件 v2 因此
重写未变 hot/cold 文件；PG v2 的整快照兼容路径在实际 Save 冲突后可能重用旧 working
copy，覆盖较新的取消、租约、策略或 Hold，甚至把终态恢复为 running。重复释放还会
做一次没有逻辑变更的 Save。此问题与原 service 包累计耗时/导出 running 风险相关，
但局部复现不证明历史 running 失败的唯一根因。

本决策只修复上述两个既有控制写，不扩展 Hold、对象版本保全、留存生命周期或业务
协议；不重交导出准入、认证 Hold 取证、租约/心跳、关联重试或任何导出检查点阶段。

## 决策

1. 创建显式使用 UpdateControl。每次实际 Save 冲突后在新鲜 control 上重新检查租户
   存在和 ID 唯一性，再将原 Hold 与一次 legal_hold.created 同 CAS 提交。ID/创建时间
   仍在调用内生成一次；原字段验证、租户作用域及权限不变，不另造请求级幂等承诺。
2. 释放使用 UpdateControlChecked。每次冲突重查同 tenant/ID 的当前记录；不存在或
   属于其他租户仍 404。首个耐久释放决定 actor/time，与一次 legal_hold.released 同
   CAS 提交；已释放则返回其原值、零 Save/零新事实，不能覆盖另一副本的首个决定。
3. 两条路径不物化或替换 v2 租户 hot/ledger，不读取/写入 WORM，不保存捕获的整快照
   覆盖当前 control。所有导出终态、lease、plan/chunks/checkpoint、共享队列/运行预算
   与其他 Hold/策略保留；旧 owner 不能因 Hold 写入重新获得终态发布权。
4. 原一次存储 operation deadline、有限冲突次数/退避与取消分类保持；重跑闭包不能
   重启预算。Save 返回错误/未知时零成功对象，保留原错误；真正已耐久的决定/事实不
   撤销，不把 close/sync/rename/Save 失败当回滚或自动重复创建的授权。已释放的零写
   回应来自当前已知 control 决定，不从未知临时文件或外部对象猜成功。
5. 当前 Hold 的导出准入/执行/终态/详情/下载认证及放行复核仍各自权威。释放一条 Hold
   不释放其他 Hold、不改变原证据成员或任务终态；不删除 WORM 或缩短 COMPLIANCE。

## 兼容、验证与限制

无新字段、路径/scope、SQL、持久/密封格式、topic 或 Proto 方法；原 HTTP 状态/授权
保持。竞争时现在观察实际当前 Hold/租户并拒绝旧观察，重复释放不再因多余 Save 失败，
仍只返回首个释放决定。v1 fallback 仍有旧快照成本，通用 Store.Update 和其他兼容
writer 未整体改造；control 历史/克隆、认证扫描和最终整块导出成本仍在，M3仍Partial。

回归在真实两租户文件/归档与重启边界核对四个 hot/cold 文件的原字节/版本/inode不变，
原回执/租约/事实保持，未知 control temp 原样保留；重复释放还核对 control inode 不变。
独立 PG pools 以实际 control 行锁及 pg_blocking_pids 确认 Save 已进入，再提交并发
取消/新 Hold/策略、同 ID 创建、首个释放或作用域变化，验证真实版本冲突后重判、事实
一次性、零额外 no-op Save 与晚 owner 零发布。失败/真正提交但结果未知、取消、实际
Save deadline 和原预算/有限重试另有回归；定向通过不代替完整 quality 与独立验收。

保留旧0014普通/独立race累计超时与同源码最终完整通过两类证据，不用局部文件写减少
或一次全量绿宣称唯一根因/长期稳定性闭环。安全扫描非零仍阻塞发布；整栈、容量、容灾、
正式合规、M4/M5 协议仍独立。沿用完整备份、停写升级/回滚与旧 writer 字段保留要求，
不清未知对象、原账本/journal/WORM/历史或旧卷，不执行业务恢复。
