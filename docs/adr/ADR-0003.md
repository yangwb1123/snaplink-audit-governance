# ADR-0003: 哈希链分段与签名检查点周期

状态：Accepted  
日期：2026-08-04  
关联：ARCHITECTURE_PLAN §10

## 背景

单一全局哈希链会把所有写入串行化，且单点失效会阻塞全部租户。需要按
租户/流分链，并周期性产出可独立验证的签名证据。

## 决策

1. `chain_scope`：默认 `tenant_id + stream_id`；stream 由
   aggregate（`tenant:aggregate:type:id`）、operation
   （`tenant:operation:id`）或 source（`tenant:source:id`）派生。
   每条流维护单调 `sequence`、`prev_hash`、`head_hash`，流间互不阻塞。
2. 分段：**每 100 个事件封一个 segment**（`AUDIT_SEGMENT_SIZE` 可配），
   段记录 first/last sequence、first_prev_hash、last_hash、事件数与
   **Merkle Root**。低流量流的 pending 段由 governance worker 周期封段
   （`SealPendingSegments`），保证每个流都有可验证 checkpoint。
3. 签名：段 manifest 的 SHA-256 用签名密钥生成 HMAC-SHA256 签名
   （参考实现）；生产由 KMS/Vault Transit/HSM 提供**只签名不可导出**
   的密钥，checkpoint 记 `algorithm`。
4. 归档：段清单与事件对象写入 WORM 目录（`O_EXCL` + `fsync` + 只读
   权限），幂等重试，已存在即视为已归档。

## 后果

- 优点：篡改可发现性按流粒度独立验证；`VerifyIntegrity` 逐流校验
  prev_hash 链、事件 hash、段 Merkle Root 与签名。
- 代价：证据链需要 WORM、密钥隔离、访问审计共同构成，不能仅凭数据库
  字段宣称绝对不可篡改。
