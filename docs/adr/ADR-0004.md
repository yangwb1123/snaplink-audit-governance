# ADR-0004: 在线查询投影与租户路由

状态：Draft（第一阶段不部署，参考实现以内存快照查询）  
日期：2026-08-04  
关联：ARCHITECTURE_PLAN §11.2、§6.4

## 背景

在线分析查询（时间线、筛选、统计）不能直接扫描不可变账本；需要独立
查询投影。投影必须可重建，且租户隔离不能依赖投影层单点。

## 决策

1. 投影存储选型 **ClickHouse**（结构化查询优先）；OpenSearch 仅在确认
   ClickHouse 无法满足全文/模糊检索需求后引入，避免双集群维护。
2. 排序键与分区：`tenant_id` 位于排序键前部；按月份分区；常用稳定字段
   展开为实体列，动态载荷保留受控 JSON（高基数 Metadata 不全部展开为
   索引列）。
3. 租户路由：普通租户共享分片，靠强制 `tenant_id` 过滤 + ClickHouse
   `user/row policy` 双重隔离；大租户可迁移到独立 shard，API 与事件协议
   不变。
4. 投影一致性：projector 消费 `audit.events.ledgered.v1` 构建投影；
   Materialized View 只用于可重建聚合；投影失败不回滚账本，通过重试和
   DLQ 修复；支持从账本或 Kafka 保留区全量重建。
5. 参考实现阶段：查询直接作用于控制面快照（`internal/service`
   `QueryEvents`），语义（时间范围必填、游标分页、租户过滤、字段脱敏）
   与生产投影一致，作为契约基准。

## 后果

- 优点：查询路径与账本写入解耦，投影可丢弃重建。
- 代价：查询最终一致（indexed 状态），不可变账本不得依赖查询投影。
