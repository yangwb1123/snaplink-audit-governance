# ADR-0033: 回执元数据读取的身份绑定、索引与共享预算

状态：Accepted  
日期：2026-10-17  
关联：ADR-0013、ADR-0019、ADR-0032

## 范围与背景

GetReceipt 原通过全局 Store.Read 物化冷历史，仅凭 lookup key 返回回执正文，随后自审计
重新开始存储预算。错误 key 下的其他 tenant/event 正文可能被返回；追加耐久后取消也
可能仍输出。HTTP 回执路由没有在认证前设置 no-store。本切片仅改该既有 scoped 元数据
读取，不重交按坐标事件认证、固定成员查询或导出续跑，不新增跨租户详情入口。

## 决策

1. 一次 Store.WithOperation 覆盖租户读取、身份核对及原一次失败关闭读自审计。使用
   ReadTenant 的 Ledger.Receipt 精确 key，并先传播 Ledger.Err；不存在仍为 404，
   请求 tenant/event 与回执正文不一致返回固定 conflict、零回执及成功读事实。
   PostgreSQL v2 使用现有精确冷索引，不物化无关 cold receipt/segment/checkpoint；
   文件 v2 使用现有冷索引。旧 v1 兼容仍物化旧快照；不是新持久模型或索引迁移。
2. 这只是已提交回执的元数据观察，不 Get WORM、不需要事件 Schema、不重建正文或
   认证全链，也不以健康邻居回执为损坏事实背书。原状态、时间、链坐标、幂等及错误
   元数据原样保留；不从 accepted/indexed/archived 推导 broker/ClickHouse 确认、
   归档当前可用、完整性或业务执行。未知历史状态不猜成成功或最新状态。
3. 锁内只读取并捕获值，独立 trail 追加在 Store.mu 外。actor-bearing 成功恰好一次
   audit.event.read，原 tenant/actor/target_type=event/target_id/detail=receipt 不变，
   内部空 actor 仍零事实。捕获后及追加成功后检查原 context；失败、超时或取消零
   输出，已经耐久但结果未知/随后取消的尝试事实不撤销，不证明字节交付。
4. 读取不 Save 旧捕获，不覆盖并发终态、lease、Hold、策略或计划/页/检查点；保持
   当前 Hold、读自审计、导出共享预算、owner/阶段 fencing 及终态不回退。回执元数据
   不是证据下载授权，不改变 selected/generating/sealed 或恢复/审批语义。
5. HTTP 在认证前设置 Cache-Control: no-store，覆盖成功和所有错误；原 read 权限、
   签名 tenant 权威与平台显式单租户选择不变，没有 Console all-tenant 例外。错绑
   只返回固定安全分类，不回显回执身份/内容、原载荷、密文、摘要或凭据。

## 兼容、成本与验证

无新路径/scope/公开字段、topic、Proto 方法、SQL/持久或密封格式，无需迁移。收紧会
拒绝此前可能被返回的错绑正文，须核对原证据，不改身份、伪造 receipt、删历史或降低
认证换成功。租户 hot/control 克隆及旧 v1 物化成本仍在；精确 receipt 读取不是所有查询
恒定成本、生产容量或完整性保证，M1 完整语义矩阵、M2 其余成本及 M3 整体仍 Partial。

回归先确定性复现错绑及读/追加预算重启，再覆盖状态原样保留、零源 Get、缺失/跨租户、
实际 Load/append 超时及取消/未知结果、原事实与独占返回。真实文件重启验证冷回执未
被改写；独立 PG pools 用自有数据库的损坏邻居记录证明全量物化失败而精确读取仍可用，
实际目标损坏仍失败关闭。实际 receipt trail append 暂停时验证同 Store 续期/取消及
当前 Hold/策略保留、晚 owner 零发布。HTTP 覆盖授权、no-store、原元数据和固定错误。

完整 quality/Web/security-scan 与专项分别记录真实命令/退出码/源码绑定，不代替随后
独立工程验收、整栈/Hosted Login、容量/容灾、正式合规或安全发布批准；安全扫描非零
继续阻塞发布。既有完整备份、停写升级/回滚及旧 writer 字段保留要求不变，不清未知
对象、原账本/journal/WORM/历史或旧卷，不缩短 COMPLIANCE、不执行业务恢复。
