# ADR-0002: 事件编码、确定性序列化与 Schema 兼容规则

状态：Accepted  
日期：2026-08-04  
关联：ARCHITECTURE_PLAN §7、§10

## 背景

同一事件在接入、哈希、归档、导出路径上必须产生完全一致的字节表示，
否则哈希链与段清单无法自洽。同时 Schema 必须版本化演进，禁止破坏性变更。

## 决策

1. 规范表示：**Canonical JSON**（`internal/domain/canonical.go`）——
   键按字典序排序、无多余空白、时间一律 UTC RFC3339Nano、数字用
   `json.Number` 保留原文。
2. 事件摘要：`EventDigest` 对规范化信封（不含服务端分配的
   `stream_id/sequence/prev_hash/hash`）做 SHA-256；链上 hash =
   `SHA-256(digest + prev_hash + sequence + stream_id)`。
3. 复合键分隔符用 `\x1f`（unit separator）：Go JSON 会把 `\x00` 转义为
   `\u0000`，PostgreSQL jsonb 解析器拒绝 NUL（22P05）；`\x1f` 可安全
   round-trip（见 `internal/store`）。
4. Schema 演进（`RegisterSchema`）只增不减：新版本不得移除前一版本的
   required 字段，也不得移除 allowed 字段；字段级加密/搜索摘要声明随
   Schema 版本走。
5. 敏感数据（密码、Token、私钥、设备凭据、完整卡号）在进入账本前被
   拒绝（`rejectSensitive`），大快照走 `payload_ref` 对象引用（生产
   对象存储，参考实现仅透传字段）。

## 后果

- 优点：哈希可复算、投影可重建、Schema 兼容性有代码级强制。
- 代价：规范化 JSON 比紧凑 JSON 略大；任何字段语义变更必须升版本。
