# ADR-0015: HotFirst 追加意图与无人重试的热冷断点恢复

状态：Accepted  
日期：2026-10-08  
关联：ADR-0003、ADR-0011；未提交恢复与 committed-cold 发布对账独立

## 背景

文件 HotFirst 的 hot → cold → control 三步可能在 cold 追加前中断。旧热正文/流头
不是已提交 receipt，不能从正文推断原 segment/checkpoint 签名，也不能把缺失回执的
幂等重试拼成 ledgered 成功。PostgreSQL 分步提交还可能使另一副本观察未提交流头。

## 决策

1. 文件 HotFirst 在持久化有变化的热文档时，一并保存 `pending_ledger`，包含本次原始
   receipt/segment/checkpoint 追加记录（最多 100 条）；不复制事件载荷。它是恢复意图，
   绝非 committed ledger truth。正常追加后内存解除标记；重启核对原记录的不可变身份
   与内容，全部已追加的标记可忽略。不可判定的 journal 不允许覆盖或丢弃。
2. `ReadPendingTenantCommit` 只锁内捕获租户、版本、原 journal、热正文、精确 Schema
   和前序 committed receipt anchors；锁外验证重建内容摘要、链哈希、连续前序、流头、
   pending hashes 与已提交回执，及原 segment/checkpoint 的身份、manifest 和签名。
   不重新签名、重新分配序号或从热正文创造一个新的“恢复 receipt”。
3. `CommitPendingTenantCommit` 必须在上述验证后调用，并重新核对 tenant/version/
   journal 完全相同，再幂等追加原记录、清除恢复元数据；整个服务恢复共用一次 Store
   deadline，继承调用方取消。追加完成而清理失败时，账本仍为已提交事实，重复恢复
   不重复分配身份。不持 Store.mu 跨远端签名验证，不在 Store 闭包嵌套 Store 方法。
4. 未完成 journal 阻止该租户普通写入，返回既有 snapshot_conflict 类；无关租户与纯
   控制面写入可继续。全快照兼容写入只能原样保留未完成租户，不能删除或改写其证据。
   摄入在共享操作 deadline 内最多先恢复再重试一次，不能无限递归或盲分配新序号。
5. API 不依赖 LedgeredPublisher：启动立即、每秒轮转一个注册租户恢复；worker 在封段/
   归档之前先恢复，坏证据阻止该租户后续证据变更。恢复本身不归档、不发 Kafka、不写
   审批、不调用业务 API。已提交后若欠发布意图，另由 ADR-0011 对账修复。
6. PostgreSQL v2 HotFirst 在同一 SQL 事务内 CAS 保存 hot 并追加 ledger；任何 cold
   错误回滚 hot CAS，其他副本不能继续未提交流头。control delta 仍独立写入，交付意图
   仍用既有 committed-cold 对账。ColdFirst 先 cold 后 hot 的既有故障语义不改变。
7. 热冷 v2 的证据选择必须有 committed receipt 并核对坐标；缺失 receipt 的 hot 不
   出现在查询/时间线/导出选择，也不能被 ArchivePending 当作已提交事实归档。摄入
   返回错误时只保留可重新读取确认的 cold receipt，否则结果未知，不冒充 gRPC
   WriteBatch COMMITTED。升级前无 journal 的 hot-only 残留不自动推断，幂等重复与延续
   其未提交热流头均失败关闭。完整性校验仍须检查已提交但损坏的正文，返回/自审计
   `valid=false` 诊断，不能把该既有无载荷诊断契约变成 409；它也不把 hot-only 算作事实。

## 限制、验证与运维

- 文件仍单写者，沿用同一账本、独占锁和密钥。journal 与 hot/control/cold 一起备份。
  不得删除 journal、复制正文到新账本或改写序号换取“恢复成功”；恢复元数据不是 TTL。
- 老版本不知道 journal，回滚前须停写、用新版本恢复所有未完成追加并核对 cold；不能
  将旧版本忽略标记当作安全回滚。升级前缺失原追加计划的历史残留需人工证据核对。
- 无标签 `audit_hot_commit_recovered_records_total` / `audit_hot_commit_recovery_failures_total`
  独立于 publisher；前者是追加操作数，不证明交付、投影完整性或全租户历史完整。
- 回归覆盖重启无客户端/无 publisher、原 receipt/封段/checkpoint、取消、版本冲突、
  capture 深拷贝、管理写不丢 journal、坏内容/哈希/签名/流头及持久污染失败关闭；
  真 PostgreSQL 注入 cold 失败核对 hot CAS 回滚及另一实例读不到未提交正文。
- v1 PostgreSQL 保留旧全快照路径；本决策不解决参考初页/Console/导出历史成本、
  租约/检查点、生产容量、全栈网络、生命周期删除、历史密钥或业务恢复执行协议。
