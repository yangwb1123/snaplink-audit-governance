# ADR-0008: 导出下载完整性 — 租户/任务绑定密封与摘要校验（export:v2）

状态：Accepted（已实现，`python3 cli.py quality` PASS）
日期：2026-08-13
关联：`docs/auto/runs/export-download-never-verifies-the-stored-conten-4ef11f9d/`
（requirements + design + adversarial reviews）、THREAT_MODEL（A2 存储级
攻击者）、`internal/security/fieldcrypto.go`、
`internal/service/governance.go`、`internal/httpapi/server.go`。

## 背景

下载路径从不校验归档对象内容：`runExport` 用平台共享密钥以
`EncryptBytes`（nil AAD，`export:v1:` 前缀）密封整个 JSONL，`downloadExport`
取回对象后直接 `DecryptBytes` 解封并 200 流出，`job.Digest` 只写不读。
后果：持有归档目录写权限的主机级攻击者（A2）可以把任意任务/租户的
合法 v1 blob 换到目标任务的 `ObjectPath`（共享密钥下 GCM 照常解开），
或放置任意内容——下载服务返回 200 且字节内容与任务记录完全无关。
审计面同步失效：`RecordExportDownload` 在取对象**之前**执行，404/500
的失败下载也会先记 `audit.event.export`，而真正需要暴露的完整性失败
（F6–F12）零审计痕迹。

## 决策

1. **v2 绑定密封（写侧）**：`runExport` 改用 `EncryptBytesBound` +
   `ExportBinding(tenantID, jobID)`，把长度前缀的规范绑定
   `export:v2:<len(t)>:<t>|<len(j)>:<j>` 作为 AEAD 关联数据。
   绑定从任务记录**派生而非存储**——无 schema 变更、无数据迁移。
   长度前缀保证对抗性 tenant/job ID（含 `|`、`:`、数字）下绑定
   不可碰撞；开放路径只重派生、不解析。
2. **版本分发开放（读侧）**：新增 `DecryptExport`，`export:v2:` 用绑定
   打开（错/缺绑定 ⇒ GCM 认证失败），`export:v1:` 保持 nil AAD 语义
   （`DecryptBytes` 原样复用，绑定参数忽略），其余前缀拒绝。旧归档对象
   永久可下载；v1/v2 互斥，v2 blob 喂给 v1 语义必然失败。
3. **服务层唯一咽喉 `VerifyExportDownload`**：租户限定重查任务 →
   409 防御（未完成/空 ObjectPath）→ 绑定解封 → 摘要格式
   `^[0-9a-f]{64}$`（空/畸形 fail-closed，镜像 `verifyContentDigest`）
   → `domain.HashBytes(plain) == job.Digest` → 仅全过返回明文。绑定与
   摘要均来自存储记录而非传输层字符串，咽喉不可部分绕过。
4. **顺序收紧**：`downloadExport` 改为 取对象 → 校验 → `RecordExportDownload`
   → 200。只有经过验证的下载才是 `audit.event.export` 治理事实（此前
   404/500 归档失败也记录该事实——行为变更，已入本决策）。
5. **失败可观测（采纳安全评审 F-2）**：验证失败（解密/摘要格式/摘要
   不等）追加 `export.download_rejected` 自审计事实（targetType export、
   targetID jobID、无内容、无 actor），治理痕迹对篡改尝试不再沉默；
   追加为 best-effort，不掩盖原始错误。404/409/归档 I/O 路径不记该事实。
6. **兼容面**：`EncryptBytes`/`DecryptBytes` 签名与行为不变（所有既有
   调用方与测试原样编译）；`job.Digest` 语义不变（仍为
   `domain.HashBytes(明文JSONL)`）；HTTP 状态码语义保留（404/403/409/500，
   仅产生 500 的**条件**变宽）；OpenAPI 下载操作补充 `500` 响应（路径/
   方法/operationId 不变，`route_contract.py` 与路由表不受影响）。
7. **回归修正（安全/测试评审 F-1）**：`TestExportEncryptedAndDecryptable`
   与 `TestExportJSONLStripsSearchDigests` 原先用 v1-only `DecryptBytes`
   打开新密封的 v2 blob——改为 `DecryptExport` + 任务绑定，并断言归档
   对象以 `export:v2:` 开头；新增 v1 遗留兼容打开用例。

## 后果

- 优点：A2 攻击者对新导出无法跨任务/跨租户换 blob（GCM 绑定，F8）；
  对遗留 v1 blob 的移动被摘要比较拒绝（F10）；位翻转（F9）与正确绑定
  下的错误内容（F12）统一 500；空/畸形摘要 fail-closed（F11）；篡改
  尝试在治理痕迹中可见（F-2 事实）。
- 代价：未验证的下载（归档 404/500）不再产生 `audit.event.export`
  事实（已决策的语义收紧）；验证失败需要多一次任务记录读与一次
  事实追加（下载为低频治理操作，成本可忽略）；回滚后 v2 blob 无法被
  v1-only `DecryptBytes` 打开（500）——回滚窗口内的 v2 任务记录保留
  摘要，可经重新导出恢复。
- 后续（非本次范围，已入 backlog）：密钥轮换/KDF 分离（独立发现）、
  Vault Transit TLS 加固（独立发现）、归档加固（威胁前提，非修复目标）、
  `X-Request-ID` 日志/响应注入清理（安全评审 F-3，独立于本变更）。
