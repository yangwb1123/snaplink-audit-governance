# ADR-0025: 分页时间线的锁外认证取证与共享操作预算

状态：Accepted  
日期：2026-10-17  
关联：ADR-0002、ADR-0013、ADR-0015、ADR-0019、ADR-0022

## 范围与背景

`OperationTimelinePage` / `AggregateTimelinePage` 原来通过 `eventsFor` 在 Store.Read
闭包内回读 WORM，慢源 Get 因而阻塞同 Store 的控制写、续期与取消；随后读自审计又
重新开始操作预算。热正文只有坐标核对，旧归档链哈希可引用保存的 SourceDigest，不能
替代重建内容认证。operation/aggregate 字段也不能在认证前决定隐藏哪条 committed 事实。

本切片只改两个分页服务入口及其 HTTP 行为，不改旧全量 timeline、operation summary、
replay/restore、Console 或查询投影；不交付持久查询快照、导出新阶段或业务执行。

后续 ADR-0026 将独立的 Console 事件页/facets 改为锁外认证读取；不把本 ADR 两个分页
时间线重新计作该后续交付，也不将两者的全历史物化/认证扫描称为已消除。后续
ADR-0027 仅将 operation summary 改用同一认证源与共享预算；旧全量/replay/restore
路径仍独立待办，不改变本 ADR 当时仅两个分页入口的范围。ADR-0028 后续再改造
operation replay 及其既有内部恢复委托的原证据读取；旧全量/aggregate replay 与
恢复整体流程仍未完成，不将本 ADR 的分页交付重复计功。

后续 ADR-0031 再将旧全量 OperationTimeline/AggregateTimeline 和服务层 ReplayAggregate
接到同一认证源与各自共享预算，保留原10000匹配上限/排序/读事实。它不新增 HTTP 路由，
不改变本 ADR 的分页行为；全历史物化/认证扫描和恢复整体流程仍未完成。

## 决策

1. 每次分页服务调用先用 Store.WithOperation 建立一次原有 deadline，再用
   Store.Snapshot 捕获独立深副本。只有捕获/后端物化持 Store.mu；远端 Get、精确
   Schema/内容/链认证、谓词和排序全部锁外。分页与读自审计继承同一 deadline，
   不按 receipt、对象或 append 重启。原 store_timeout/503、调用方取消/499、计数
   与生产超时不变；Store 闭包内不嵌套 Store 方法。
2. 从目标租户的 committed receipts 锚定，核对 map key 与正文 tenant/event 身份；
   属于本租户的 key 或 receipt 正文出现错绑均失败关闭。没有 receipt 的热正文或
   journal 不是事实，v1/v2 都不作为输出成员。其他租户的证据不 Get、不认证或输出。
3. 通过已有 queryEvidence 取原热正文或 archived receipt 指向的 WORM，核对精确
   身份/链坐标、Schema ID/version、重建内容摘要与链哈希；还须核对精确 Schema
   正文的 tenant/id/version。缺失精确版本不使用最新版本替代，失活历史 Schema
   不因停用就失去可读性；保护字段只在内部认证时重建，不把解密值替换进返回事件。
   HTTP 保留既有派生搜索摘要剥离。先认证后评估 operation/aggregate 条件，损坏
   的谓词字段不能让证据消失为正常空页/404；坏/缺证据拒绝整页而非跳过或截断。
4. 使用同一次捕获的正文与版本精确目录，不把后续 catalog 写混进已捕获认证。
   这是一次读取的观察点，不是跨后端事务快照或对后续目录变更的原子证明；新请求
   重新捕获并按当前精确目录认证。只追加独立读事实，不保存旧快照覆盖并发 control、
   新任务、终态、租约、计划、页进度或检查点。
5. 排序、默认/最大 page_size、cursor 线面与原 scope 检查保持：operation 按
   occurred_at/sequence/event_id，aggregate 按 aggregate_version/event_id。
   count 为本次总匹配数，不是剩余条数；仍是 live 分页，迟到/新提交可改变下一次
   count，不宣称 ADR-0013 的固定成员集、全历史完整性或防漏读。旧全量方法的
   10000 条保护上限不变，不给分页端点新增任意截断/历史容量上限。
6. actor-bearing 成功页仍须 append-before-serve 恰好一个原 audit.event.read，
   保留 tenant/actor/target/detail；内部空 actor 保持零事实约定。捕获/取证/认证/
   分页/追加失败或取消时返回零结果，不返回部分 items/count/cursor。已进入耐久
   追加边界的未知结果不能撤回，可能留下尝试事实，不作为字节交付或业务执行证明。

## 成本、兼容与未交付项

无新 REST 路径、scope、公开字段、Kafka topic、gRPC 方法、SQL/密封格式或持久元数据，
不需迁移。认证收紧会拒绝以前可能被过滤隐藏的坏正文、错绑回执或不可认证的精确目录；
须修复原证据/目录，不能清历史、改身份/版本、伪造 receipt 或退回弱认证换成功。

捕获仍可能物化全局历史，随后认证扫描本租户全部 committed 证据；page_size 不是源
扫描/内存上限，未交付索引、恒定内存或生产容量 SLA。旧全量/summary/replay/Console、
参考初页、其余 Hold 路径的成本仍分别待办。当前 Hold、读自审计、共享导出预算、owner
fencing、终态不回退及 selected/generating/sealed 语义完全不变，M3 整体仍 Partial。

## 验证与部署边界

回归先在真实归档 Get 暂停处复现原 Store.mu 阻塞；覆盖热/冷正文与谓词字段污染、
精确 Schema/回执错绑、缺源/版本、protected 大整数、owned 结果、hot-only/tenant 隔离、
live count/顺序、捕获目录并发变更、Get/append 同一 deadline、取消/真实超时计数一次、
追加失败零结果，以及独立 PG17 pools 的并发续期/取消与控制写保留。固定失败文案，
不把原载荷、密文、搜索摘要或凭据写进测试日志。

完整 quality、Web 与 security-scan 分别保留真实命令/退出码，组件通过不代替外部独立
工程验收、整栈/Hosted Login、生产容量/容灾、正式合规或安全发布批准。不降认证、预算、
生产超时或门禁规则；安全扫描非零继续阻塞发布。不改变既有备份、WORM/COMPLIANCE、
升级/回滚的停写核对与旧 writer 字段保留要求。
