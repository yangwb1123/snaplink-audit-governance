# ADR-0029: 导出创建与新后继的认证 Hold 预检及准入复核

状态：Accepted  
日期：2026-10-17  
关联：ADR-0002、ADR-0013、ADR-0014、ADR-0019、ADR-0020、ADR-0021、ADR-0022、ADR-0023

## 范围与背景

prepareExport 已在独立深快照后锁外回读，但仍调用旧 Hold helper：事件可以在重建内容
认证前被原查询/Hold 谓词过滤，派生搜索 sidecar 的缺失、值或格式又可能隐藏真正被
Hold 覆盖的证据。预检完成至新任务提交之间，其他副本还可以修改活跃 Hold 集；仅凭
旧观察创建新任务，不符合失败关闭的准入语义。

仅改 CreateExport 和 RetryExport 创建新后继的预检/提交，不重交已有详情/下载门禁、
租约/心跳、取消/单后继关联、selected/generating/sealed 或业务执行。既有后继的重复
请求仍只返回安全控制摘要，不重新读证据或创建任务。无需新增外部业务决策或权限。

## 决策

1. 保留原 QueryEvents 及其失败关闭读自审计，然后捕获独立深快照，复用
   holdBlockingExportEvidence：从 committed receipts 锚定，认证 map/body 身份、精确
   Schema tenant/id/version、重建内容及链 hash，之后才评估原查询与当前 Hold。
   本租户 key 或 receipt 正文属于该租户时均须核对，不能把坏正文改成其他租户而被
   跳过。坏/缺证据拒绝预检，不成为空选择或创建成功；hot-only/journal 不是事实，
   其他租户完整证据不读取。缺失精确 Schema 不以最新版本替代，停用历史版本可读。
2. 敏感条件仅从精确 Schema 声明 searchable 的认证原值，按条件自身 bound/legacy
   格式重算；不信任 sidecar 的存在、值或格式，保持加密字段和大整数精度。认证不
   把解密内容替换进返回事件，不新增载荷/密文/筛选/搜索摘要元数据或日志。
3. 无候选、已释放、其他租户或时间不相交的 Hold 不触发额外源 Get；原 QueryEvents
   自身仍按原语义取证与自审计，不能把“零额外 Hold Get”称为整个请求零源读取。
   有候选时仍认证本租户 committed 证据后判定；零匹配选择不被 blanket Hold 拦截，
   保留最低匹配 Hold ID、半开时间窗和当前证据语义，不从页大小或 cursor 推断 Hold。
4. 允许预检返回请求内的本租户活跃 Hold 集 HMAC，复用既有私有用途绑定，不持久化、
   不公开，也不是持久计划/授权或业务版本绑定。新任务显式使用 UpdateControl：每次
   实际 Save 冲突后在新鲜 control 上重新运行原绑定、准入与事实闭包，不能让整快照
   兼容路径把之前物化的 working copy 覆盖当前 control；不重写未变的租户 hot/cold。
   新任务的同一次 control CAS，在共享
   队列 128/tenant32 准入及保存 job/创建事实前重新核对该绑定；集合变化返回 409，
   零新任务/成功事实，要求显式刷新重试，不暗中重选或重启预算。包括无候选时观察到
   的空集合；CAS 冲突重跑闭包也须核对原绑定，不能用新集合替换它换成功。
5. 只绑定本租户当前活跃集合，其他租户 Hold 或无关策略/租约变化不使请求冲突，也不
   被旧快照覆盖。对新后继，原终态/申请人/完整 query/唯一后继的现有复核先执行；
   若并发已创建合法后继，仍可返回该 metadata-only 摘要，不通过它取得证据授权。
   原终态不退回 pending，旧 cursor 仍清除，新后继不继承计划/页/检查点。
6. 每个 create/retry 继续共享一次原 Store operation deadline：原 query、读事实、
   深快照、锁外 Get/认证、Hold 判定、拒绝事实或最终新任务 Save 都继承它。只在锁内
   捕获/核对自有数据，Store 闭包不重入；慢 Get 不阻塞续期/取消。当前 Hold 匹配仍
   独立提交一次原 export.blocked，返回兼容 forbidden/reason=legal_hold/租户内 Hold
   ID；独立拒绝事实也仅在新鲜 control 上追加，不保存捕获的历史/覆盖并发取消、租约、
   Hold 或策略，不替换未变的 hot/cold 文件。已释放但此前被观察为阻断的本次尝试可以
   保守拒绝，事实不证明字节交付。
7. 读自审计、Get、Save、超时或调用方取消均零成功响应，不撤销已提交但回报未知的
   尝试事实或任务。新任务 Save 未知时不唤醒本执行、不推断回滚；后续既有调度器仍
   可看到真正耐久的 pending，新后继可通过原关联幂等核对，不能盲目重放外部写入。
   不新增 CreateExport 请求级幂等承诺。HTTP 创建在认证前设置 no-store，和既有 retry
   一样覆盖成功/全部错误；原 tenant/owner/权限、固定脱敏错误及 body-only 筛选不变。

## 兼容、成本与未交付项

无新公开字段、路径/scope、Kafka topic、Proto 方法、持久元数据、SQL 或密封格式，无需
迁移。收紧会拒绝此前被过滤隐藏的坏证据/精确目录，以及预检期间 Hold 变化的创建尝试；
须核对原证据或显式重新请求，不能清历史、伪造 receipt、降认证/预算或修改终态换成功。

新任务 CAS 是当前活跃 Hold 集的准入观察点，不是跨后端原子证据快照或后续下载授权。
事实/目录可在随后变化，执行/进度/终态与详情/下载继续各自重查原认证、当前 Hold、
自审计和 owner/阶段 fencing。全局 running2/tenant1、lease2分钟/心跳30秒均不变。

原 QueryEvents 初页当时未在本 Hold 切片重写；后续 ADR-0030 改造它的认证前置/敏感
条件，预检的当前 Hold CAS/原读事实仍独立权威，不重新计功本 ADR。深快照/全历史认证
扫描、旧 v1 物化、共享 control
成本、最终整块合并/密封与认证流式下载、其余准入、M4/M5 和业务执行仍独立待办。
没有恒定内存、完整性、生产容量/公平 SLA 或正式合规保证，M3 整体仍 Partial。
control-only 收紧只覆盖上述导出准入/拒绝提交，不改通用 Store.Update 或其余兼容 writer，
也不将减少无关写入当作旧 service 累计超时/导出 running 的唯一根因证明。

## 验证与部署

先在真实第二次源 Get 暂停/实际 Save 冲突边界确定性复现 stale Hold 准入，并复现热/归档
sidecar 污染绕过。回归覆盖原查询/当前 Hold 谓词前认证、精确 Schema/receipt 绑定、
bound/legacy/大整数、空选择/无候选/租户隔离、Hold 增加/释放与无关 control、CAS 重跑、
一次 deadline/读自审计、实际 Get/Save 超时或取消、失败/未知 Save、单后继核对、真实
文件重启及 HTTP 认证先于 Get/no-store/脱敏错误。纯矩阵使用真实内存 Put/Get/Save/append，
不把它当文件耐久性；原真实 FileStore 锁外回归保留。独立 PG pools 在 Get 暂停时续期、
取消及修改 Hold/策略，验证当前 CAS 失败关闭且不覆盖并发终态/control。

真实文件回归进一步核对两租户四个 hot/cold 文件的原字节/版本和 inode 在允许、Hold
拒绝及 control 临时文件失败后不变，原冷回执/租约/独立读事实重启仍在。独立 PG pools
以实际 control 行锁和 pg_blocking_pids 同步 Save（不是 sleep 猜时序），并发提交新 Hold、
满额队列或邻居取消/策略后制造真实版本冲突：原绑定/预算必须重新核对，终态和租约
不得被旧副本复活。该 oracle 修复前确定性失败，完整自验与随后独立验收仍分别要求。

完整 quality、Web 与 security-scan 各自保留真实命令/源码绑定/退出码；专项或模型自验
不代替随后独立工程验收、整栈/Hosted Login、容量/容灾、正式合规或发布批准。安全扫描
非零继续阻塞发布。沿用既有完整备份、停写升级/回滚及字段保留要求；不清未知对象、
账本/journal/WORM/历史或旧卷，不缩短 COMPLIANCE、不执行业务恢复。
