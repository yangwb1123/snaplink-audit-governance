# ADR-0021: 密封对象检查点与终态提交续跑

状态：Accepted  
日期：2026-10-16  
关联：ADR-0013、ADR-0014、ADR-0017、ADR-0019、ADR-0020

## 范围

本切片仅恢复 **Put 已成功且检查点已提交、终态尚未提交** 的导出。恢复不重新选择
事件、不重新生成 JSONL、不再次 Put；不是逐页/逐块生成续跑、大文件下载或业务恢复。
检查点提交前崩溃仍按既有租约失败收敛，不能从未知对象或临时文件猜测成功。

后续 ADR-0023 在生成前增加独立的 selected 固定成员计划：已有合法计划时可跳过选择
继续整块生成，sealed 保存与消费计划同 CAS；两阶段均未提交的崩溃仍失败。该后续
不把本 ADR 的 sealed 续跑冒充逐块生成，也不从未知 Put 对象猜计划。后续 ADR-0024
再为新多页任务增加真实逐页生成进度；本 ADR 的最终 sealed 格式/终态门禁不变。

## 持久模型与认证

- control 增加私有 `export_checkpoints`：每个活跃任务最多一个 sealed 阶段记录，格式
  version=1、seal_version=2，保存 tenant/job、任务绑定、对象引用、密封字节 SHA-256、
  原 JSONL SHA-256、事件数、创建时间及 HMAC。它不进入公共 DTO/hot/日志/URL，不复制
  载荷、密文、原始筛选或搜索摘要，不使用 15 分钟查询 cursor 充当长期检查点。
  原执行也复核既有查询的 10000 个匹配身份预算，不截断成功；不是更高的容量承诺。
- 用独立用途标签的 HMAC 绑定完整原任务身份、申请人、原筛选（包括旧 cursor 的绑定，
  但恢复不使用它）、retry_of、created_at、started_at；另一个用途标签认证整个检查点。
  格式/密封版本不认识、任务漂移、未来时间、错绑或坏 MAC 均失败关闭，不覆盖未知记录。
  API/worker 须继续使用相同签名/加密环境；没有历史 Key ID/自动轮换降级。
- 原执行在锁外验证选中事件的精确 Schema、重建内容及 committed receipt/链坐标后密封。
  Put 成功后，只有当前未过期 owner 能将检查点与一次 `export.checkpointed` 原子提交。
  Save 未知结果不当作成功，也不删除对象；若检查点实际已持久化，后续可恢复。
- 恢复只读检查点指向的原对象：核对精确密封字节摘要、强制 v2 tenant/job AEAD、明文
  摘要/JSONL 计数与最新 committed receipt 坐标。不会以运行元数据创造账本事实。
  现有下载兼容格式不变；认证前无明文输出。

## 状态、fencing 与预算

- 同一任务保持 running；仅在原合法 lease 到期后，以共享 control CAS 换新随机 owner，
  保存 `export.resumed`。不继承旧 owner、不延长旧 lease、不重置 started_at，更不将
  failed/cancelled/completed 退回 pending。健康 owner 不能被抢占。
- 检查点任务已经占 running 配额，接管仍检查全局 running≤2、租户≤1；共享排队
  128/32 和进程有限 dispatcher 不变。过预算不接管、不扩大配额。无检查点的到期任务
  继续原子 failed + export.recovered；合法检查点保留给 dispatcher，不伪报为已恢复完成。
- 检查点保存、接管、终态各自重新核对当前身份/owner/版本。终态还须精确匹配本次
  捕获的检查点，完成结果只能引用它的原对象/摘要/计数。取消或换主后的晚写零发布；
  迟到 Put 可能留下无引用 sealed WORM 对象，既不删除也不从路径推断可恢复。

## Hold、自审计与失败

- 原执行及恢复的远端取证均锁外进行；一次终态验证共享一个 Store operation deadline，
  不逐对象重启预算，不阻塞续期/取消。历史快照物化和整块 AEAD 内存仍在。
- 完成前重新检查当前 Hold，并把本租户活跃 Hold 集绑定到终态 CAS；锁外检查后 Hold
  有任何变化则拒绝该完成写，保留检查点供后续重新检查。匹配 Hold 原子失败并写
  export.blocked，详情/下载仍保留独立 Hold 门禁。
- 检查点终态的 Hold 取证从本租户 committed receipts 锚定，在原查询/Hold 的任何事件
  谓词之前验证身份、精确 Schema、重建内容及链哈希。不能仅因 sealed 对象/HMAC 有效，
  就信任当前热正文、归档正文或其中的派生索引。缺失正文、损坏或 Schema 无法认证时
  拒绝完成、保留原 running 检查点，后续合法过期接管可重新检查，不误判为空结果。
- 搜索 sidecar 不受 SourceDigest 认证，不能以其值/存在/格式决定 Hold 不匹配。仅对
  Schema 声明可搜索且存在的字段，使用精确重建的认证原值，按查询条件的 bound/legacy
  格式重新推导比较，包含加密字段和大整数；原文/摘要不进入新元数据、事实或日志。
  当前查询重叠与最低匹配 Hold ID 语义保持（包括当前迟到证据），但不改动原输出成员。
  无候选/时间不相交仍不读源对象；源 Get、认证和读自审计共享原 deadline、锁外执行。
  本决策当时仅加固 sealed 检查点终态；后续 ADR-0022 将同一认证判定复用于详情/
  下载放行，未将创建/重试预检、执行选择等其余 Hold 路径或历史成本算作已整体改造。
- 对象认证/账本坐标失败原子失败并写 `export.checkpoint_rejected`；不发布路径。
  Get/Store/取消/超时或读自审计失败不宣称完成，保留 running 检查点到下次租约接管。
  每次完成验证须以内部服务 actor governance-worker 失败关闭追加 audit.event.read，
  不把旧申请人推断成当前用户授权；完成与一次 export.completed 同 CAS。未知旧申请人
  仍不能被用户代办取消/重试，既有 tenant/subject/scopes 门禁没有放宽。
- 完成/失败/所有者取消时，同 CAS 移除已知活跃检查点与 lease；这是运行元数据结束，
  不是删除历史事实或 WORM。未知/错绑检查点不自动清理。重试仍创建新任务，不继承它。

## 部署与验收边界

无新增 REST 路径/scope、Kafka topic、gRPC 方法、SQL 表或合法历史密封格式变更。
文件/PG v1/v2 control 深克隆、tenant delta 和备份必须保存新 map；禁止会丢字段的
旧 control writer/API/worker 混跑。停写升级/回滚，保留完整 control、ledger/hot/journal、
发布确认、密钥及未知远端结果；不手改 lease/终态或清理 WORM 换成功。文件仍单写者。

回归须覆盖真实 Put/Get/Save、文件重启、检查点前后断点、晚写/取消、版本/绑定/证据污染、
当前 Hold/自审计/deadline 与独立 PG CAS/预算。完整 quality、Web（如改动）和安全扫描
分别保留证据；本 ADR 不授予发布、正式合规、生产容量或跨仓业务执行批准。M3 全部
检查点续跑仍为 Partial，逐页/逐块执行计划另行交付。
