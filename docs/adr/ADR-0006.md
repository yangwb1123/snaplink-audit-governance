# ADR-0006: 租户 ID 键框架校验 — 校验 + 边界解析，而非转义

状态：Accepted（已实现，`python3 cli.py quality` PASS）
日期：2026-08-06
关联：`docs/auto/runs/validate-tenant-ids-to-close-cross-tenant-key-pr-37692075/`
（requirements + design artifacts）、architecture plan §10（聚合证据链）

## 背景

复合快照键由 `store.StreamKey(t, s) = t + "\x1f" + s`（`KeySeparator =
"\x1f"`，0x1F）拼接。`CreateTenant` 只做 `TrimSpace` 空值检查，因此租户
ID 可内嵌 0x1F：`StreamKey("a\x1fb","s") == StreamKey("a","b\x1fs")`。
三个治理扫描（`CreateAggregateCheckpoint`、`VerifyIntegrity`、
`ArchivePending`）用 `HasPrefix(key, tenantID+KeySeparator)` /
`HasSuffix` 选择键，前缀/后缀匹配无法区分该碰撞，导致恶意租户
`"a\x1fb"` 的段/checkpoint 被并入租户 `"a"` 的签名聚合证据与归档（读
侧泄露、写侧共享序列/哈希状态）。

## 决策

1. **新增校验（写入侧，防止新碰撞）**：`store.ValidTenantID` 拒绝
   控制字符（含 0x1F）、空白、路径分隔符（`/`、`\`），返回
   `domain.ErrInvalid`；`CreateTenant` 在任何快照变更之前执行该校验
   （无副作用：不建租户、不写 admin action、不查重）。拒绝式而非
   白名单式：非 ASCII 字母、`:`、`.` 等合法形态不受影响。
2. **新增边界解析（读取侧，同时关闭存量数据）**：`store.SplitTenantKey`
   用 `strings.Cut` 要求键恰好包含一个 `KeySeparator`，解析为
   `(tenantID, rest)`；零/多个分隔符的键不属于任何租户（fail-closed）。
   三个治理扫描全部改为精确组件相等；`ArchivePending` 中被并入的
   `StreamKey(tenantID, "")` 快捷分支删除（被新规则吸收）。
3. **不改键格式、不迁移快照**：键保持字节级不变；行为仅在多分隔符键
   （即碰撞键）上改变——它们从所有租户的治理范围中排除。

## 备选方案

- **转义/编码键**：需快照迁移、无法修复存量键、不能满足验收
  AC-1（创建时校验）。否决。
- **白名单字符集**：拒绝合法 ID 形态并引入长度/格式策略，超出需求。
  否决。
- **仅校验不解析**：无法关闭已存在的恶意租户（F1）。否决——两条控制
  必须同时落地。

## 后果

- 正向：键空间对合法租户 ID 前缀单射；碰撞键从所有治理扫描中
  fail-closed 排除；纯增量 API（两个新导出符号），HTTP 契约不变
  （`ErrInvalid`→400 既有映射）；无部署协调、纯代码回滚。
- 代价：存量多分隔符键（streamID 含 0x1F，OQ-1 未做 streamID 校验的
  残余风险）失去治理覆盖（F2/F5）；存量恶意租户仍可写侧碰撞
  （F1），需运维按预升级审计清单重建；`VerifyIntegrity` 对含此类键
  的租户报告更少的段数（预期的 fail-closed 语义，发布说明）。
- 残余风险跟踪：streamID 的 0x1F 校验（OQ-1）作为后续需求；可选
  `governance.unparsable_keys` 计数暴露 F2 证据。
