# ADR-0038: 既有恢复申请创建的控制增量提交

状态：Accepted  
日期：2026-10-18  
关联：ADR-0017、ADR-0019、ADR-0020、ADR-0023、ADR-0024、ADR-0028、ADR-0035、ADR-0037

## 背景与有限范围

CreateRestore 的原认证回放之后，仅新增 pending_approval 控制记录和一次 restore.created，
却仍走通用 Store.Update。文件 v2 替换未变 hot/cold；PG v2 在真实 Save 冲突后可能
重新保存旧整份 control，覆盖并发决定、当前 Hold/策略、租约续期或导出取消/阶段撤销。
这会恢复原已撤销的运行权，而非只有无关文件成本。

本决策只改上述既有创建的控制提交，不增加恢复产品能力。实际文件/PG回归可确定性
复现局部写放大和控制覆盖；不是旧 service 累计10m超时/原导出 running 的唯一根因
证明。旧0014自验/独立失败及同源码收尾完整通过都保留，不能以局部修复或全量绿抹消。

## 决策

1. 创建显式使用 UpdateControl。每次实际 Save 冲突后，只将本次原新请求与一次创建
   事实合入新鲜 control，不保存旧物化快照。原新 ID/tenant/申请人/operation/reason/
   created_at 在调用内生成一次；冲突不生成第二个请求，不重复回放或追加重复事实。
2. v2 控制提交不物化/替换 hot/cold，不再为控制记录重写原证据。保留并发恢复决定、
   导出终态、lease、selected/生成页/sealed 阶段、当前 Hold、策略和其他控制事实。
   取消不能因此回到 running，续期不能回到旧到期时间；晚 owner 仍零发布。
3. 原字段验证、tenant/权限与 HTTP 分类不变。原内部 ReplayOperation 继续按 committed
   receipt、精确 Schema、重建内容/链认证后本地折叠，保留10000匹配上限和空actor零
   读事实策略。回放与控制提交仍为原来的独立操作预算；仅提交自己的重试共用一次原
   deadline/有限退避，不把整个 CreateRestore 宣称为单次预算或跨后端原子证据快照。
4. 原请求与一次 restore.created 同 CAS；失败/未知 Save 返回零成功对象，已耐久请求/
   事实不撤销，不把 fsync/rename/关闭/取消错误当回滚或自动重新创建的授权。客户端
   结果未知须只读核对；本决策不新增请求级幂等协议、可重放业务命令或执行回执。
5. 此提交不 Get/Put WORM、不执行业务调用；前置原认证回放仍读取原源。审批不是执行，
   不增加正式 scopes、版本绑定计划/有效期或M4/M5协议。GetRestore旧兼容读取和通用
   Store.Update、v1/共享control历史成本、原回放扫描均未整体改造。当前导出Hold、必要
   读自审计、owner/阶段fencing及128/32队列、running2/tenant1共享预算继续独立权威。

后续：ADR-0043 将既有 GetRestore 详情改为 v2 control-only 观察，并在原一次预算内
检查捕获后取消；不改本 ADR 的创建提交、前置回放、静默读策略或分离预算。

## 验证、兼容与限制

真实两租户文件/归档、原认证selected计划及当前Hold回归：成功创建或未知temp阻断Save
都不替换四个hot/cold文件，原字节/版本/inode、完整证据/邻居控制/事实与重启保持。
未知temp不删除或截断；原回放仍恰读一次源、不Put、不增加静默内部读事实。

独立PG17 pools用真实control行锁及pg_blocking_pids确认Save已经在途，再提交并发
取消或续期，以及另一恢复决定/Hold/策略；selected、真实生成页和sealed三个阶段均
核对版本增量、完整原证据与当前控制，取消后晚owner不能发布。续期须推进原共享测试
时钟，并在竞争前后复核当前owner真实运行权，不能把未来心跳/旧观察时钟冒充健康续期；
保存冲突不重生原请求创建时间。首次完整工程自验通过后的该夹具加强须重新完整验收，
不把前一版本的绿套到新源码。测试必须用完整Snapshot
检查冷证据；ReadControl/leaseSnapshot不含冷回执，不能用其零长度作源Get数量依据。
新增夹具曾混淆这两者，失败保留，改为真实物化证据而不是降低断言。原修前控制覆盖
证据与该夹具错误分开判断。实际Save失败/未知/取消/超时、原有限重试和提交预算另验。

无新字段、路径/scope、SQL、topic、Proto方法、持久/密封格式或迁移。沿用完整control
（请求/决定、任务/关联/lease/计划/页/检查点）、ledger/hot/journal/确认/原密钥备份与
停写升级/回滚；旧writer可能覆盖字段，不能混跑。不得清历史/未知对象/旧卷或缩短
COMPLIANCE。文件仍单写者，共享API/worker使用PG；不提供通用关闭或远端强停保证。

全service race/JSON与逐测试/原导出阶段、专项/真实PG、完整quality/Web/security与随后
独立验收分别绑定源码留证，不以定向替代全量，不改原5秒导出等待/10m包上限或生产
超时/认证/规则。少写无关文件不等于所有累计耗时/历史running根因闭环、容量SLO或
长期稳定性。M1/M2/M3整体Partial，M4/M5、整栈/Hosted Login/容量/容灾/正式合规独立
待办；安全扫描非零继续阻塞发布，本ADR不授予发布批准。
