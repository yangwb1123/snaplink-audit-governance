# ADR-0040: 既有 Schema 注册的控制 CAS 与演进重判

状态：Accepted  
日期：2026-10-18  
关联：ADR-0002、ADR-0017、ADR-0019、ADR-0020、ADR-0023、ADR-0024、ADR-0039

## 背景与有限范围

RegisterSchema 仅改变 control 中的版本定义与一次 schema.created，却使用通用
Store.Update。真实文件 v2 因而替换未变 hot/cold、推进 hot 版本；真实 PG Save
冲突后，兼容路径会再次保存先前物化的整份 control，而不是重跑原注册闭包。这既
可能覆盖当前导出取消/续期/阶段、Hold、恢复决定与策略，也可能丢掉并发新定义，
跳过对当前最高版本、重复版本和最近前序 required/allowed 规则的重新判断。

本决策只修该既有注册提交，不增加产品能力或改造通用 Store.Update。文件写放大
与实际控制覆盖/校验遗漏的确定性复现是局部根因证据，不是旧 service 累计10m
超时或原导出 running 的唯一根因证明。旧0014失败与同源码收尾通过分别保留。

## 决策

1. RegisterSchema 显式使用现有 UpdateControl。每次实际 Save 冲突后在新鲜 control
   上重跑原闭包：当前租户存在、同租户/Schema最高版本、重复 key、最近前序的
   required/allowed 兼容规则，再提交本次原新定义与一次 schema.created。
2. 保留原错误顺序：缺租户404，低于当前最高版本400 invalid_request，重复最高
   版本409，原前序兼容拒绝400；拒绝不 Save、不追加本次成功事实。不新增最新
   版本专用读取规则，合法历史精确版本仍供摄入/认证使用，原前向跳版本保持。
3. 静态字段/key framing/资源上限及原时间/Active默认处理不变。请求定义在调用
   内确定，提交冲突不创建另一版本、不重启操作预算。原一次 deadline、有限
   冲突重试/退避和取消/超时分类保持，不增加 WORM Get/Put 或独立读事实。
4. v2不替换未变 hot/cold，也不回写旧整快照覆盖当前终态、lease、selected/页/
   sealed、其他Schema、Hold、恢复决定或策略。当前 Hold/必要读自审计、共享
   128/32队列与running2/tenant1、精确owner/阶段fencing继续独立权威；取消不
   回到running，续期不退回旧时间，原终态不能因注册而重开。
5. Save失败/未知返回错误，不报告注册成功；实际耐久定义/事实不撤销，不把
   sync/rename/close/取消错误当回滚或授权盲重发。先只读核对实际版本/事实；
   重复注册仍是原冲突，不引入请求幂等、Schema重签名/自动替换或业务执行。

## 验证、兼容与限制

真实文件回归保留两租户、实际归档/淘汰、原认证selected计划与当前Hold。修前
成功和未知temp失败均替换四个hot/cold inode、改变两个hot文件字节/版本；修后
核对字节/版本/inode、完整Snapshot/原事实和关闭重启。未知temp原样保留，注册
本身零源I/O/独立读事实，重启后的当前Hold仍拒绝原导出访问，旧精确定义不变。

真实PG17独立pools用control行锁和pg_blocking_pids同步实际Save，再提交并发
取消或健康续期、恢复决定、当前Hold与邻居策略；selected/真实生成页/sealed均
核对完整证据、版本增量和晚owner零控制发布。续期推进共享观察时钟并核对运行
权。另在实际冲突后验证租户缺失、重复/更高版本、较新前序required/allowed变化
均重判拒绝、零额外Save；并发已耐久定义与事实保留。自有goroutine早退也join。
Backend.Save矩阵另覆盖有限冲突/耗尽、明确/真正提交后错误、实际deadline与取消，
核对原一次预算、精确定义和一次原事实；不冒充文件或PG耐久验收。

首次修后全service诊断真实失败（包456.220s，非10m超时）：原故障夹具现在能观察
Schema初始化的一次控制写，两条旧测试却把累计2/1当成单次Ingest应有的1/0。只在
这两条原测试捕获真实初始化后的基数，断言Ingest增量仍精确1/0；不清零counter、
不改初始化三次API/Save故障序列或任何I/O/事实/超时断言。新增真实文件护栏确认
初始化、armed注册失败、disarmed成功的累计计数依次1/2/3，失败不发布定义/事实、
两份hot/cold不改写。保留原失败与源码绑定，修改后重新完整验证，不以专项抵销。

无新字段/路径/scope、SQL、topic、Proto方法、持久/密封格式或迁移。文件仍单写者，
共享API/worker使用PG，完整control（含精确Schema和任务/关联/lease/阶段）、ledger/
hot/journal/确认/原密钥一并备份、停写升级和核对回滚；其他旧writer仍可能覆盖
字段，不能混跑。不删历史/未知temp/WORM，不降低COMPLIANCE、认证或生产deadline。

ListSchemas、通用Store.Update/v1与全历史/锁内物化成本仍在。全service race/JSON/
逐测试及原导出阶段、专项/真实PG、完整quality/Web/security与随后独立验收分别
绑定源码留证；少写四个无关文件不是整包wall下降、容量SLO或所有累计耗时/running
根因闭环。M1/M2/M3总项仍Partial，M4/M5业务协议、整栈/Hosted Login、容量/容灾/
正式合规仍独立待办，安全扫描非零继续阻塞发布，不以本决策自授豁免或发布批准。
