# ADR-0005: 合规归档与密钥管理

状态：Draft（生产依赖外部 WORM/KMS，参考实现用本地只读目录与固定密钥）  
日期：2026-08-04；2026-08-06 修订：默认密钥 fail-fast（`service.New` 校验 + `-check-config`）；开发认证默认失败关闭见 ADR-0007  
关联：ARCHITECTURE_PLAN §11.3、§14

## 背景

合规证据链要求事件对象、段清单与签名 checkpoint 进入不可篡改存储，
且租户数据加密密钥必须与数据分离管理。数据删除权与法定审计留存冲突时
需要明确处置边界。

## 决策

1. 归档格式：canonical JSON Lines / Protobuf segment + Zstandard 压缩；
   manifest 记录事件范围、Schema、对象摘要与链头；Parquet 仅作为分析
   副本，不是唯一证据格式。对象路径按 tenant/日期/stream/segment 组织。
2. 合规模式：生产开启 Object Versioning、Object Lock（或等价 WORM）、
   Legal Hold、跨区域复制；使用独立归档账号；**应用服务不拥有缩短合规
   保留期的权限**。参考实现用本地目录模拟：`O_EXCL` 创建、`0o440`
   只读、`fsync` 落盘，幂等重试。
3. 密钥层级：每租户 envelope encryption（租户 DEK 由平台 KEK 包装），
   字段级加密使用 AES-GCM + 关联数据（`internal/security`）；生产密钥
   由 KMS/Vault/HSM 管理，应用实例不能导出私钥。`AUDIT_SIGNING_SECRET`
   与 `AUDIT_ENCRYPTION_KEY` 是生产必配的两个不同强随机值：任一为空、
   等于公开默认值、两者相同或少于 32 个配置字节（非开发模式）时启动失败关闭（`service.New`
   校验 + 二进制非零退出，`-check-config` 预检）；该长度门禁不提供熵保证，不能通过给弱口令补
   padding 代替随机生成。建议分别运行两次 `openssl rand -base64 48`。开发模式须显式
   `AUDIT_ALLOW_DEV_SECRETS=true` 才允许旧默认行为（仅限本机）。更换弱密钥不自动迁移既有密文、签名或
   checkpoint；迁移由操作员控制。
4. 数据删除：与不可变审计冲突时优先数据最小化、主体标识令牌化、密钥
   销毁与法定留存策略；具体处置必须由法务/合规要求形成 ADR，不由技术
   系统自行推断。
5. 完整性：`VerifyIntegrity` 校验链、Merkle Root 与签名；KMS 不可用时
   停止生成新签名 checkpoint，不伪造归档成功。

## 后果

- 优点：证据链独立于数据库与传输层，可审计、可重建。
- 代价：归档验证与恢复演练是运维义务（每季度 Kafka 恢复、PITR、
  投影重建、WORM 验证、地域切换）。
