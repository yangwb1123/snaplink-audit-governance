# ADR-0046: 控制深拷贝成本分离与已提交账本的正查找提示

状态：Accepted（控制器审查后的架构决策；不授予工程或发布通过）  
日期：2026-10-29  
关联：ADR-0002、ADR-0015、ADR-0019、ADR-0021、ADR-0023、ADR-0024、ADR-0034、ADR-0044

## 修前证据与归因边界

先在未改生产实现、未改原三个测试的 worktree 上，执行一次指定的 race 对照：

- Hold list 分配测试失败：同一 control、1→32 个真实 hot 样本，160→183 次分配。
- Retention read 通过，217→217；Ingest archived-history 测试通过，不能声称其失败复现。
- 新增真实文件观察仍保留原归档源、逐次 Ingest/Save/append/fsync、四份 hot/cold 文件和
  重启；control 始终为同一 7743 字节、outbox=0、管理事实=11。其修前 Hold 为195→200，
  policy 为191→169。**这些差值不证明 v2 ReadControl 遍历了无关 hot 历史**：v2 control
  本来就不含那些正文。原分配波动的唯一原因并未确定，不把它等同于原累计10m/running故障。

专用 Store 回归把纯内存复制与文件 I/O、动态事件图、账本查找分开，固定每组4次分配调用
及64次计时调用；时间仅作观察，不设新的时间门槛。修前/修后同一工作量的观察为：

| 工作量 | 修前 | 修后 |
|---|---:|---:|
| 同一 control，携带1/32个随后丢弃的事件，分配/调用 | 527 / 8053 | 230 / 233 |
| 必须独占的1/32个动态事件，分配/调用 | 244 / 7765 | 237 / 7783 |
| 同一 outbox 事件的1/32个动态叶，分配/调用 | 285 / 1174 | 239 / 1132 |
| 10k历史末尾 committed 命中，时间/调用 | 171.162µs | 312ns |
| 10k历史负查找，时间/调用 | 151.058µs | 151.362µs |

CPU/alloc profile与源码支持两个局部事实：旧 cloneControl 经完整 cloneSnapshot 后才
清空证据字段，且控制元数据做 JSON 编解码；旧 committed 查找遍历 records。动态图的
反射克隆也有真实成本，但它承担类型/独占/失败关闭语义，本 slice 不重复实现或绕过它。
上述是指定资源条件下的局部样本，不是吞吐、磁盘唯一归因、稳定性或容量 SLO。

## 决策与不变量

1. cloneControl 显式复制完整控制字段，不序列化再解析元数据，不先复制再丢弃 Events、
   Receipts、Streams、Segments、Checkpoints。controlSnapshot 复用此边界；完整快照/
   tenant hot/动态事件的既有克隆器不重写。控制观察不是证据认证，真正证据路径仍自行
   验证 committed ledger、精确 Schema、内容/链与 WORM，不能从控制副本制造事实。
2. 来源 allow-list、Schema四组切片、Hold释放时间、导出起止时间、恢复批准/拒绝时间、
   聚合 roots/refs、outbox，以及 lease/selected成员/pages/sealed 元数据均独占。
   顶层 maps/lists 沿用 normalize；旧 JSON copy 对空 optional 控制切片的省略语义保持，
   required plan Members 与动态事件保留 nil/empty。时间值本身不可变、时间指针另复制。
   删除 JSON 往返不能放行原先非法的元数据时间：逐字段严格 RFC3339 检查，失败沿用
   json.MarshalerError/Time.MarshalJSON 类，零部分副本/零控制提交。
3. LedgeredOutbox 逐事件沿用 domain.CloneEvent，保留动态 map/list/命名类型、精确
   json.Number/整数、typed nil及独立条目；循环、函数、channel、不支持的键/不可检查
   字段失败关闭。不能用 JSON 往返降精度或浅复制来换分配数。
4. TenantLedger 只新增内存 recordPositions **正查找提示**。位置必须在范围内，且实际
   records 条目的 tenant/type/key/version 与请求完全相符才返回原已提交记录；缺项、
   nil、越界、错位或伪造命中回退原历史扫描。提示不证明不存在，不保存索引为事实，
   不改变 pending优先/committed边界、父视图、版本、duplicate/conflict 或读取错误。
   未改变原 committedRecordKey、receipt/idempotency索引及其语义。
5. 不改 tenant/source授权、CAS重跑闭包、状态机/终态、owner fencing、当前Hold、共享
   128/32与running2/1、必要读自审计、原operation预算或重试次数。不改原hot/cold/control
   顺序、fsync、journal、归档/发布顺序或失败后的未知结果，不执行业务恢复。

## 验证、代价与未闭环项

- 新测试统一 TestControlClone/TestControlCost 前缀，显式分类 Snapshot 全部21字段，
  递归填充/双向变异验证嵌套字段与别名；另测 nil/empty、动态类型/精度/typed nil、
  每个控制时间位置的非法年份/时区、坏outbox零提交、被丢弃证据零遍历及坏提示兜底。
- 指定 control/ledger/split/export plan/generation/checkpoint/lease/HotFirst/ColdFirst/
  UTCtrl race 定向命令一次通过，覆盖真实文件重启、页/密封阶段、读自审计、终态与
  并发fencing等原回归；不改原测试、样本、准备/调用次数、5秒等待、10m包上限、生产
  deadline、TMPDIR或文件系统。没有新增真实PG跨pool/CAS验证，不能以本轮定向代替它。
- 原三个测试修后仅一次命令 `-race -count=3`，9次全部通过；Hold三轮均52→52，
  Retention三轮均48→48。原文件SHA256未变。真实文件专用观察修后53→53/48→48，
  control/四份证据、原事实、归档与重启保持；不把通过当作累计失败的唯一根因闭环。
- 正查找提示新增 O(K) 内存；本样本正查找由0增至2次分配/调用。负查找和新身份摄入
  仍可能扫描历史，pending扫描、共享control历史、动态outbox复制、v1全快照、查询/
  Hold认证扫描与最终整块导出成本仍在。不以负索引缺项换恒定复杂度，不扩大核心改造。
- 原文件1500行、函数220行、decision55及fanout预算/规则均未修改；fmt/filesize/
  complexity/architecture/directory-fanout定向静态检查通过。完整quality与race全集按
  阶段分工由控制器集成后独立执行，实施 worker 未运行全集；结果须绑定集成源码
  另行留证，本决策不授予工程通过。
- 可用扫描器下执行一次 security-scan，退出1：govulncheck以Go1.26构建的分析器不能
  加载当前Go1.27源码；CLI提前返回，gosec未执行。没有重装/降级、修改依赖、规则或
  豁免，也不将工具不兼容等同于安全通过；发布仍阻塞。控制器应固定兼容的
  GOTOOLCHAIN=go1.26.10 独立重新扫描，保留解析失败与实际告警的不同裁决。
