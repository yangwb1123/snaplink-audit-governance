# ADR-0009: 平台 token 的 `tenant_id` 过滤 — 空哨兵语义（admin/actions）

状态：Accepted（已实现，`python3 cli.py quality` PASS）
日期：2026-08-15
关联：`docs/auto/runs/get-api-v1-admin-actions-silently-ignores-the-do-153f5b0a/`
（requirements + design）、`internal/service/governance.go`、
`internal/httpapi/server.go`、ADR-0006（键框架）、ADR-0007（dev 认证）。

## 背景

`GET /api/v1/admin/actions`（operationId `listAdminActions`）的 OpenAPI 契约
承诺平台 token 可用 `tenant_id` 过滤，但服务层谓词
`if platform || action.TenantID == tenantID` 在 `platform == true` 时短路，
静默丢弃已验证的过滤值——平台 token + `?tenant_id=tenant-a` 返回全部租户的
自审计动作（跨租户保密性泄露）。租户作用域 token 一直正确。

## 决策

1. **服务层谓词修正**（`internal/service/governance.go:961`）：
   `if platform || action.TenantID == tenantID` →
   `if (platform && tenantID == "") || action.TenantID == tenantID`。
   `tenantID == ""` 是平台 token 的"全部租户"哨兵：平台且无过滤 → 全部；
   平台且有非空过滤 → 只过滤该租户；非平台 → 恒按 `claims.TenantID` 过滤。
2. **边界层哨兵收敛**（`internal/httpapi/server.go` `tenantFor` 平台分支）：
   平台 token 且无 `tenant_id` 查询（或为空串）时返回 `""`，不再回落到
   `claims.TenantID`。理由（实现期发现，见下）：dev token 的
   `claims.TenantID` 恒等于其 subject（`dev:platform:platform-admin` →
   `"platform"`），若回落到该值，平台无过滤读会被错误地限定到不存在的
   `"platform"` 租户（AC-2 行为验证失败：count=0 而非 4）。生产 JWT 平台
   token 的 `tenant_id` claim 为空，本就返回 `""`；本决策使 dev 路径与
   生产 JWT 路径一致，且与 `tenantFor` 平台分支既有注释
   （"Empty stays legal (all-tenants read)"）一致——代码此前与自身注释矛盾。
3. **不改动**：签名 `ListAdminActions(tenantID string, platform bool, limit int)`
   不变；OpenAPI 文档、`store.ValidTenantID` 键框架校验（ADR-0006）、
   `require()` 权限/租户上下文检查、非平台分支全部不变。
4. **`CreateExport` 空租户 fail-closed**（安全评审 S-2.1 后续）：空哨兵随
   `tenantFor` 修复对 dev 平台 token 可达（生产 JWT 平台 token 空 claim 本就
   可达）；空作用域导出在 `runExport` 选择阶段按精确 TenantID 匹配选不到任何
   事件，不存在“导出全部租户”语义，且此前会产生空任务 + 空租户自审计记录。
   决策：`CreateExport` 在一切副作用（读事实、任务、自审计记录、worker
   goroutine）之前拒绝空 `tenantID`（`domain.ErrInvalid` → 400），与 R2
   法律保留门的 fail-closed 顺序纪律一致。带 `tenant_id` 的平台导出与租户
   token 导出完全不变。

## 设计偏离记录（相对 design-610d45b2）

设计文档声称"no handler change；等价表 `(true, "")` 可达自 'no
`?tenant_id=`'"。该前提对 dev token 不成立：`tenantFor` 无查询时回落到
`claims.TenantID`（dev token 恒为 `"platform"`），因此仅改服务谓词会让
AC-2（无过滤 → 全部租户，count=4）失败（实测 count=0）。批准的需求
REQ-2（"平台 token 无 tenant_id 时必须继续返回全部租户"）优先于设计的
实现备注；修正为决策第 2 条。生产变更面由"一行"扩大为两处（服务谓词 +
`tenantFor` 平台分支），两者共同构成该接口的完整契约；其他端点在 dev
模式下的平台 token 行为随 `tenantFor` 修复同步从 `"platform"` 回落变为
`""`，与生产 JWT 一致，无既有测试翻转（已全量验证）。

## 后果

- 正面：平台 token 的 `tenant_id` 过滤按文档生效；无过滤读保持全部租户；
  租户 token 行为不变；dev 与生产平台路径语义统一。
- 负面/注意：平台 token 无过滤读在其他端点（query/export 等）的 dev 模式下
  从 `"platform"` 租户作用域变为空哨兵——对生产 JWT 无行为变化（其 claim
  本就为空），仅影响 dev token；`CreateExport` 对空租户改为 400（决策第 4
  项），依赖旧“空任务 202”的脚本需显式传 `tenant_id`；滚动部署窗口内旧节点
  仍泄露过滤请求的全量数据（见 release-notes 行为变化条目）。
- 备选否决：Option B（签名改为 `allTenants bool`）——需改动 handler 与全部
  19 处服务级调用点，零行为收益；handler 内二次读 `tenant_id` 违反
  `TestTenantForBoundaryGuard`（raw read 必须在 `tenantFor` 内唯一存在）。
