# ADR-0007: 开发认证默认失败关闭 — 默认关闭、严格环境变量解析、预检仅认环境变量白名单

状态：Accepted（已实现，`python3 cli.py quality` PASS）
日期：2026-08-06
关联：ADR-0005（默认密钥 fail-fast，同类决策）、THREAT_MODEL §3、
`docs/auto/runs/flip-dev-authentication-to-fail-closed-default-o-4295a7de/`
（requirements + design artifacts）

## 背景

`cmd/audit-api/main.go` 长期把 `-allow-dev-auth` 默认设为 `true`，且
`boolEnv` 在 `strconv.ParseBool` 解析失败时回退到默认值（fail-open）。
后果：任何默认部署（未配置 JWT 信任源、未设置 `AUDIT_ALLOW_DEV_AUTH`）中，
未认证的远程攻击者都能铸造无签名的 `dev:<tenant>:<role>` 令牌，其中
`dev:platform:platform-admin` 映射 `Claims.Platform=true`，经
`Claims.Allows` 获得全部权限（含跨租户读写/导出/治理操作）；预检
`-check-config` 从不校验认证配置，照样退出 0。这是实时可利用的完整平台
接管面（安全评审 F1 Critical / F2 High）。

## 决策

1. **默认关闭**：`-allow-dev-auth` 默认值改为 `false`
   （`strictBoolEnv("AUDIT_ALLOW_DEV_AUTH", false)`）。裸启动不再有任何
   信任源时失败关闭，保留字节一致的错误串
   `no JWT verification trust source is configured`。显式
   `AUDIT_ALLOW_DEV_AUTH=true`（或 `-allow-dev-auth=true`）后运行时语义
   不变：开发令牌仍是合法的运行时信任源。
2. **严格环境变量解析**：`boolEnv` 替换为 `strictBoolEnv`，四个布尔变量
   （`AUDIT_ALLOW_DEV_AUTH`、`AUDIT_ALLOW_LOCAL_HS256`、
   `AUDIT_ALLOW_INSECURE_JWKS_LOOPBACK`、`AUDIT_ALLOW_DEV_SECRETS`）取值
   非法时在 `flag.Parse` 之前以非零退出并在 stderr 指明变量名与值，
   不再静默回退（`audit-governance-worker` 的重复实现保持不变——其回退
   为 `false` 属失败关闭，作为已记录的非目标）。空值视为未设置（回退）。
3. **预检网关**：`-check-config` 与启动使用同一套 `ValidateConfiguration`
   规则校验认证配置，零信任源配置不再被预检放行；开发认证白名单仅认
   环境变量 `AUDIT_ALLOW_DEV_AUTH=true`（与运行时标志默认共用同一条
   `strconv.ParseBool` 解析路径），`-allow-dev-auth` 标志单独无法满足
   预检，失败时输出可审计标记
   `check_config=fail auth=dev_auth_flag_not_allowlisted`。预检成功输出
   `check_config=ok ...` 保持字节一致。
4. **迁移要求**：部署方须在运行时环境（而非仅 CI 预检步骤）显式设置
   `AUDIT_ALLOW_DEV_AUTH`（`true` 仅限开发）；清理历史非法取值（过去
   对 `AUDIT_ALLOW_DEV_AUTH` 意味着 fail-open `true`，对其他三个变量
   意味着静默 `false`，现在一律硬失败）；从 CI 预检命令中移除
   `-allow-dev-auth`。回滚 = 重新部署上一版二进制（纯配置面变更，无
   数据迁移）。

## 后果

- 优点：默认部署不再存在可铸造的开发令牌面；错误配置在预检/启动即
  失败关闭，不再被 CI 放行；失败原因可审计。
- 代价：依赖默认开发认证的本地部署需要显式环境变量（verify 栈
  `deploy/docker-compose.verify.yml` 已设置，零 compose 变更）；历史上
  依赖默认 `true` 的部署会启动失败并收到保留错误串——这是预期中的
  强制迁移信号。
- 后续（非本次范围，已入 backlog）：JWKS 缓存/singleflight、错误信息
  oracle 清理、`exp`/`nbf` 严格类型、HS256 密钥强度下限、CI 托管与
  生产部署路径。
