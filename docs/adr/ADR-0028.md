# ADR-0028: 操作回放的锁外认证取证与共享操作预算

状态：Accepted  
日期：2026-10-17  
关联：ADR-0002、ADR-0013、ADR-0015、ADR-0019、ADR-0025、ADR-0027

## 范围与背景

ReplayOperation 原委托旧全量时间线，在 Store.Read 闭包内 Get WORM；慢源读取阻塞同
Store 的租约续期、所有者取消和控制写。热正文可以在内容认证前参与 operation 选择，
旧归档链 hash 又可能只引用保存的 SourceDigest，不能认证被改变的 changed_fields。
读自审计随后还重新开始操作预算。回放虽然没有业务副作用，错误的重建状态仍不可信。

本切片只将 ReplayOperation 改用已有 readTimelineEvidence，并给既有 HTTP operation
replay 端点设置全部响应 no-store。PreviewRestore/CreateRestore 已经以空 actor 委托
该方法，因此其原证据读取一并继承认证与锁外行为；不改变其读事实兼容策略、权限、
创建/审批控制提交或业务边界。旧全量 timeline 与 ReplayAggregate 保持原路径，恢复
整体工作流的证据/业务版本计划、scopes、独立执行回执和执行能力不在本决策中。

后续 ADR-0031 加固上述当时仍走原路径的旧全量服务方法和 ReplayAggregate，复用认证源、
锁外 Get 与各自一次共享预算，保留原聚合顺序/10000匹配上限/单次读事实。不新增聚合
回放 HTTP 路由或生产调用，不重复计算本 ADR 的操作回放；历史扫描与恢复整体仍未完成。

## 决策

1. 每次 ReplayOperation 调用先以 Store.WithOperation 建立一次既有 deadline，再
   由 readTimelineEvidence / Store.Snapshot 捕获独立深副本。只有捕获/后端物化持
   Store.mu；源 Get、认证、选择、排序及本地折叠均在锁外。捕获至一次读自审计共享
   同一原预算，不按对象或 append 重启；原 timeout、取消及 store_timeout 分类/
   计数不变，不在 Store 闭包内嵌套调用 Store 方法。
2. 从目标租户 committed receipts 锚定成员，核对 map key 与 receipt 正文身份，再
   验证原热/WORM 正文的身份/链坐标、精确 Schema 身份/版本、重建内容与链 hash，
   最后才评估 operation 和折叠 ChangedFields。本租户坏/缺 committed 证据拒绝
   整次观察，不能过滤隐藏为正常空回放/404、跳过或返回部分 state/count/sequence。
   hot-only/journal 不是事实；其他租户完整证据不 Get/认证。缺失精确 Schema 不取
   最新版本替代；停用历史版本仍可按其精确定义读取。派生搜索 sidecar 不成为回放
   成员/状态依据，认证时的内部重建不会把解密的 payload 替换进返回状态。
3. 保留原最多 10000 个**匹配**事件的保护上限；超过即 ErrInvalid，无截断成功或
   成功读事实。该上限不是全历史扫描/字节/内存上限。匹配事件仍按 occurred_at、
   sequence、event_id 升序，本地逐事件应用 changed_fields.after，nil 删除状态键。
   last_sequence 保留最后折叠事件的 sequence，**不是最大序号、跨流水位或执行回执**。
   新调用可见迟到/新提交事件；没有固定成员游标、业务版本计划或完整性证明。
4. actor-bearing 成功恰好 append-before-serve 一次原 audit.event.read，保留
   tenant/actor、target_type=operation、target_id 与 detail=replay；不委托会
   额外自审计的公开时间线。捕获/Get/认证/上限/追加失败或取消返回零 ReplayResult。
   追加已提交但结果未知、或成功追加后取消，均不输出状态，不撤销尝试事实，也不将
   尝试事实当字节交付证明。只追加独立 trail，不写回捕获快照覆盖并发 control。
5. 内部空 actor 继续零读事实，包括已有恢复预演/创建委托；这不是新增授权或自审计
   豁免。预演仍零业务调用/零 control 保存，创建仍单独提交 pending_approval 与原
   创建事实，审批仍只记录决策。原证据认证失败则预演/创建均拒绝，无部分提案或新
   pending run。此处 replay 的共享预算**不声明整个 CreateRestore 的读取与后续
   控制提交成为单次预算或原子证据/业务版本绑定**；该整体改造仍是独立待办。
6. HTTP 保留 audit:operation:read、签名 tenant 权威与平台显式单租户选择，不获得
   Console 的 tenantless/all-tenant 例外。认证前设置 Cache-Control: no-store，
   覆盖成功和所有错误；坏内容的内部错误固定脱敏，不向日志/URL/浏览器持久化写入
   Token、原载荷、密文或搜索摘要。返回仍为原 ReplayResult，没有新增执行入口。

## 成本、兼容与未交付项

无新路径、scope、公开字段、topic、Proto 方法、持久元数据、SQL 或密封格式，无需迁移。
认证收紧会拒绝以前可能被筛选隐藏或折叠的坏证据/精确目录；必须修复原证据/目录，不能
删历史、伪造 receipt、改身份/版本或降认证换成功。

仍物化历史、排序 receipt keys 并认证扫描本租户全部 committed 证据，保存匹配事件后
本地折叠。10000 保护上限与一次 deadline 不是恒定内存、生产容量 SLA 或完整性保证。
旧全量/aggregate replay、恢复整体工作流、参考初页/其余 Hold 历史成本、ClickHouse
facets/完整性、导出最终整块密封/认证流式下载和 M4/M5 仍未整体完成。租约/阶段 fencing、
终态不回退、当前 Hold、读自审计与共享 128/32、2/1 预算不变，M3 整体仍 Partial。

## 验证与部署

先在实际 FileStore Get 暂停处确定性复现 Store.mu 阻塞，并复现热/归档 operation 与
changed_fields 等内容污染被接受；再验证 receipt/精确 Schema、未匹配坏证据、hot-only/
其他租户、捕获目录、原 fold/精确数字/owned/live/上限、Load/Get/append 同一次 deadline、
取消、未知追加与零结果。纯认证/预算矩阵使用实际内存 Put/Get/Save/append，真实文件
源锁外及文件重启另验；独立 PostgreSQL pools 在 Get 暂停时执行同 Store 续期、另一
pool 取消与 Hold/策略修改，读取不得覆盖已提交终态/control。恢复委托覆盖原静默读、
认证失败零创建与审批不是执行；HTTP 覆盖授权先于 Get、原 DTO、no-store 和固定错误。

完整 quality/Web/security-scan 分别保留真实命令、退出码与源码绑定，不以专项或模型
自验冒充随后独立工程、整栈/Hosted Login、生产容量/容灾、正式合规或发布批准。安全
扫描非零继续阻塞发布。沿用现有完整备份、停写升级/回滚、旧 writer 字段保留及 WORM/
COMPLIANCE 约束；不清未知对象、账本/journal/历史或旧卷，不产生业务副作用。
