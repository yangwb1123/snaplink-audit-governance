# ADR-0031: 旧全量时间线与聚合回放的锁外认证读取

状态：Accepted  
日期：2026-10-17  
关联：ADR-0002、ADR-0013、ADR-0015、ADR-0019、ADR-0025、ADR-0028、ADR-0030

## 范围与背景

OperationTimeline / AggregateTimeline 的旧全量服务方法，以及委托后者私有 source 的
ReplayAggregate，仍通过 eventsFor 在 Store.Read 闭包内 Get WORM。热正文在重建内容
认证前参与选择；归档链 hash 也可能只引用保存的 SourceDigest，不能认证被改变的
aggregate_version 或 changed_fields。慢 Get 阻塞同 Store 的租约续期/取消，读事实
追加又重新开始操作预算。

本切片只改这三个既有服务方法。HTTP 时间线继续调用已交付的分页方法，不切回全量；
ReplayAggregate 当前没有生产调用或 HTTP 路由，不新增路由、scope 或业务执行。
不重新计功分页时间线、operation summary/replay、固定成员查询或导出生成阶段。

## 决策

1. 旧全量私有 source 改用 readTimelineEvidence：Store.Snapshot 捕获独立深副本，
   锁内只有捕获/后端物化；远端 Get、精确 Schema/内容/链认证、所有选择谓词及排序
   在锁外。删除已无调用者的 eventsFor 包装，避免重新引入锁内取证。
2. 从目标租户 committed receipts 锚定，先核对 map/body tenant/event 身份、原正文
   链坐标、精确 Schema tenant/id/version、重建内容与链 hash，再评估 operation 或
   aggregate 条件。本租户坏/缺 committed 证据拒绝整次读取，不能被不匹配谓词隐藏
   或输出部分事件/state/count/sequence；hot-only/journal 不是事实，其他租户证据
   不 Get/认证。缺失精确 Schema 不取最新版本替代，停用历史版本仍可读。
3. 每个公开服务方法使用一次原 Store.WithOperation 预算，涵盖捕获、Get/认证、
   选择、排序/本地折叠至一次失败关闭读自审计。不按对象或 append 重新计时；原
   store_timeout/取消分类、计数与生产 timeout 不变。失败或追加后取消零结果；已经
   提交但回报未知的尝试事实不回滚，也不证明字节交付。Store 闭包不重入。
4. 保留最多 10000 个**匹配事件**的原保护上限，超限 ErrInvalid、零输出/成功读事实，
   不截断成功；不变成历史扫描/字节/容量保证。operation 仍按 occurred_at/sequence/
   event_id 升序，aggregate 仍按 aggregate_version/event_id 升序；并列版本不以
   发生时间或接入序号代替 event_id 排序。
5. ReplayAggregate 继续按原聚合顺序本地应用 changed_fields.after，nil 删除键；
   last_sequence 仍为最后折叠事件序号，不是最大值、跨流水位或业务执行回执。
   直接调用私有无事实 source，不能增加一次 delegated timeline 事实。三个方法
   保留原 target/detail/actor 编码、actor-bearing 一次 append-before-serve 和内部
   空 actor 零事实策略；不新增授权或自审计豁免。回放无业务调用/状态写入。
6. 使用捕获的同一精确目录认证本次证据；目录变更由新请求重新观察，不混用后来
   版本换成功。返回事件/本地状态由调用方独占，保护 payload 字段不被内部认证明文
   替换。只追加独立读事实，不保存捕获快照覆盖并发终态、lease、Hold、策略或导出
   计划/页/检查点；当前 Hold、owner/阶段 fencing、终态不回退与共享预算完全不变。

## 成本、兼容与未交付项

无新公开字段、路径/scope、topic、Proto 方法、SQL、持久元数据或密封格式，无需迁移。
认证收紧会拒绝此前可能被筛选隐藏或折叠的坏内容/目录，须核对原证据，不能删历史、
改写身份/版本、伪造 receipt 或降认证换成功。API 线面/分页行为不扩展，三条服务签名不变。

仍物化历史、排序 receipt keys 并认证扫描本租户 committed 证据；旧全量和回放仍保存
匹配事件，原上限/deadline 不是恒定内存或生产容量 SLA。新调用可见迟到/新提交，
不是固定成员、跨后端原子快照或全历史完整性证明。旧跨租户单事件兼容 helper、
其他历史成本、ClickHouse facets/完整性、导出最终整块合并/密封和流式认证下载、
其余跨副本准入、恢复整体版本计划/scopes/独立执行回执、M4/M5 仍未完成，M3仍Partial。

## 验证与部署

修复前在实际 FileStore Get 暂停处确定性复现三个入口阻塞续期/取消，并复现热/归档
谓词/版本/changed_fields 等污染被接受或隐藏。回归覆盖 receipt/精确 Schema、未匹配
坏证据、hot-only/v1/v2/tenant 隔离、捕获目录、保护字段/精确大整数/owned/live 顺序、
原10000匹配边界、Load/Get/append同一次deadline、取消/未知追加零结果。纯矩阵使用
真实内存 Put/Get/Save/append，不当作文件耐久性；实际文件重启验证原认证读和持久
谓词故障拒绝，原 receipt/Schema 不变。独立 PG17 pools 在实际 Get 暂停时续期、取消、
修改 Hold/策略，验证终态/control 不被覆盖，另一 pool 可见的持久故障不能过滤隐藏。

完整 quality、Web 和 security-scan 各自记录真实命令/退出码/源码绑定，组件或模型
自验不代替随后独立工程验收、整栈、容量/容灾、正式合规或安全发布授权。安全扫描
非零继续阻塞发布。沿用既有完整备份、停写升级/回滚及旧 writer 字段保存要求；不清
未知对象、原 ledger/journal/WORM/历史或旧卷，不缩短 COMPLIANCE，不执行业务恢复。
