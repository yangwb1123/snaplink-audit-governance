# ADR-0018: TLS 配置的受限读取与 DLQ state 的安全文件边界

状态：Accepted  
日期：2026-10-12  
关联：ADR-0001、ADR-0017

## 背景

剩余路径告警来自 gRPC client CA 与 DLQ state。两者不是同一个目录策略：
DLQ state 是进程可变数据，不能随 symlink 重定向；证书是运维配置，须兼容
Kubernetes projected secret 的 `..data` 相对链接，但不能无界读取任意文件。
仅增加一个包装或关闭 G304 不足以缩小实际 I/O 的信任边界。

## 决策

1. gRPC server certificate、private key、client CA 均在启动/预检通过同一 bounded
   PEM loader 读取，再用原 `tls.X509KeyPair`/`AppendCertsFromPEM` 校验。每个文件
   最大 4 MiB，Stat 和实际读取均验证上限，O_NONBLOCK 打开，非 regular inode
   拒绝，FIFO 不等写者。close 错误保留，不打印 PEM、密钥或 token。
2. TLS loader 用 `os.OpenRoot` 捕获**运维配置的父目录**，`Root.OpenFile` 只打开
   basename；该配置目录/其挂载和父路径是受信部署边界。允许 root 内的相对
   symlink，兼容 `tls.crt -> ..data/tls.crt`；叶链接逃出 root、绝对链接或 loop
   失败关闭。需要跨目录证书时配置其真实父目录，不能以叶链接跳出 root。
   非 Linux loader 失败关闭，不回退无界/阻塞读取。
3. 不改变 TLS 1.2 最低版本、RequireAndVerifyClientCert、gRPC credential wiring、
   现有 bearer/source/tenant 鉴权和 plaintext 拒绝。加载发生在启动/预检，**不提供
   热加载**，逐文件读取也**不证明跨 cert/key/CA 原子快照**；轮换时 key mismatch
   仍失败关闭，须重启并独立验收部署的 secret/certificate 权限及信任链。
4. DLQ state 的 load/classify/legacy conversion/rebuild/append/torn-tail repair/lock
   全部使用 ADR-0017 的 DataDir/OpenDataFile：所有祖先及叶 symlink、special、
   多链接文件拒绝；分类先捕获 verified fd，再从同一 fd Stat/有界 probe，不能
   把 unsafe missing-file 当成空成功。旧格式及旧权限读取不自动 chmod。
5. DLQ rewrite 在一个 pinned parent 内 O_EXCL 创建独占、唯一 0600 temp（名字
   使用 crypto/rand，不是凭据），从 actual fd fsync、close，再 renameat 和实际
   parent fsync。清理只 unlink 本次创建的 basename，保留未知 temp；既有 sync/
   temp/flock 实例测试边界保留，temp factory 产物验证同一空私有 regular inode。
6. 原 v1/v2 JSONL 字节、legacy tenant 显式 opt-in、tenant/event injective identity、
   torn trailing line 规则、flock 有界等待、多进程 union、append O(1) 写成本和
   追加后早释放锁保持。关闭/同步/rename/cleanup 错误不能更新成功内存 mark 或
   提交 DLQ offset；磁盘可能已 durable，错误是未知结果，允许幂等重试，非回滚。

## 限制、部署与回滚

- 数据目录仍须为真实受控 Linux 本地 POSIX 目录/挂载；文件 owner、ACL、服务 UID
  和父目录写权限由运维核对。描述符不防特权主机/mount 管理或真实目录搬迁，不是
  正式 WORM；本批没有改变 ledger、journal、签名、业务审批或业务执行。
- TLS 的受限 root 不证明 CA/证书配置正确或硬链接来源；运维不能让不受信身份写入
  secret root/配置。不得将 TLS 的 symlink 容许策略用于可变 state/ledger。
- DLQ load 与一次性 conversion 仍可物化全部历史 marks；未增加任意固定容量上限
  丢弃旧 marks，也未声明流式、恒定读取内存或生产容量验收。
- 升级前停 DLQ writers，核对 state/lock 的链接与所有权，备份原 state 与显式 legacy
  tenant scope；未知 temp 保留、不作为 marks 或恢复事实。新 temp/state/lock 0600，
  旧权限不批量更改。两个受支持 writer 可共用原 flock/local POSIX state，不能
  误套 ledger 的单写者规则，也不能把支持扩展到 NFS/SMB 或独立拷贝预算。
- 回滚前停 writers，核对 durable marks/union 和 scope，保留原文件与未知残留。
  不清空 state 换成功；旧版本允许链接重定向，不是安全回滚。TLS 配置超过 4 MiB、
  向 root 外跳的叶链接须在上线前整改；不放宽 listener/mTLS 来换启动成功。

## 实现与验证

- `internal/grpcapi/tls_file_linux.go` 与 `tls.go`；`internal/kafka/replay_state*.go`；
  `internal/fsutil/secure_temp.go`。无业务 API、SQL、JSON/JSONL 或生成 proto 迁移。
- Linux temp/TLS/replay 新边界覆盖 actual parent replacement、owned cleanup、
  projected mount/真实 `..data` 切换、root escape、FIFO、硬/软链接、权限、大小
  上界、同步边界后 target 替换及错误不更新内存；测试私钥只在私有临时目录生成，
  不写入仓库、日志或浏览器持久存储。
- 原有 union、两进程 flock、fsync/crash/torn-tail、O(1) append、tenant 隔离、
  auth-blocked offset barrier 与真实 TLS/plaintext socket 回归继续保留。
- 定向 race 与完整 quality/security-scan 分别记录；仍需独立 Hosted Login、真实
  PG/Kafka/WORM/整栈、容量、容灾、正式 scopes/业务执行及合规验收。
