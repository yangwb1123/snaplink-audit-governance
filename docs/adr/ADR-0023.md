# ADR-0023: 持久固定成员计划与 selected 阶段续跑

状态：Accepted  
日期：2026-10-16  
关联：ADR-0013、ADR-0014、ADR-0017、ADR-0019、ADR-0020、ADR-0021、ADR-0022

## 范围

在 JSONL 生成前持久保存已认证的固定成员计划，重启后跳过选择、从原成员继续生成。
这在 ADR-0021 的 post-Put sealed 阶段之前增加一个真实 selected 检查点，不把心跳、
新任务 retry 或重新执行实时查询称为续跑。**仍是整块 JSONL/AEAD 生成**：selected
之后尚未提交 sealed 的字节工作可以重做，不保存逐页/逐块字节进度，也不交付分块下载
或任何业务执行。M3 整项仍 Partial。

后续 ADR-0024 为新选择超过 100 成员的任务增加 v2 计划/逐页生成进度，认证复用已
提交页、只生成剩余页；新单页与本 ADR 的历史 v1 计划仍保持上述整块路径。所有页
之后仍整体合并/密封，不交付流式下载；不把本 ADR 当时的 selected 阶段重复计功。

## 持久模型与证据绑定

1. control 增加私有 `export_plans`，每个活跃任务至多一个，version=1、format_version=1
   表示现有 JSONL + export:v2 密封格式。保存 tenant/job、创建时间、任务 HMAC、有序
   members 与计划 HMAC。member 仅含原 EventReference（身份/流/序号/哈希/发生时间）、
   精确 Schema ID/version 与独立用途的 Schema 定义 HMAC；不是 ledger/WORM 的新事实。
   不复制 payload、密文、原始筛选、搜索摘要、owner 或输出字节，不进入公共 DTO/hot/
   自审计详情/日志/URL。原查询仍仅在既有 job 中，绑定完整原申请人、retry_of、原查询
   （含 cursor）、created_at 与首次 started_at；purpose 与查询/sealed 检查点分离。
2. 沿用 10000 个匹配身份和 4 MiB 编码上限，超限失败，不截断成功。计划只存在于已占
   running 配额的作业，同一 control CAS 仍全局 2/tenant 1，队列仍 128/32；保存计划也
   检查当前运行上限。没有额外长期计划配额或查询的 15 分钟 TTL。成员有序且身份唯一；
   版本、格式、时间、身份、绑定、MAC 或互斥阶段不合法均失败关闭，不清理未知记录。
3. 首次选择从 committed receipts 锚定，先认证精确 Schema、内容与链，再评估查询和
   当前 Hold。敏感条件从认证原值按条件自身的 bound/legacy 格式推导，不信任 sidecar
   的存在/格式/值。热无回执残留不变成事实；缺失或损坏的 committed 证据不是空选择。
   这仍扫描历史，不声称固定计划代表跨后端原子快照或全租户完整性。
4. 内部 governance-worker 读自审计失败关闭；当前未过期 owner 才能将计划与一次
   `export.planned`（`stage=selected version=1`）同 CAS 提交，保存时复核当前 Schema
   定义绑定。Save 失败/未知不生成或 Put，不猜原计划是否已提交。

## 执行与 fencing

- 无 selected/sealed 检查点的崩溃仍按既有租约失败。合法 selected 计划在原 lease
  到期后保留 running，由原有限 dispatcher 以共享 CAS 换新 owner，写 export.resumed
  的 selected 阶段；不重置 started_at、不抢健康 owner，不将任何终态回退 pending。
  接管已经占用原运行槽，仍检查全局≤2/tenant≤1，超预算拒绝，不扩大阈值。
- 恢复只读取原有序成员的最新 committed receipt/hot/WORM，重验身份、坐标、发生时间、
  内容/链与精确 Schema 定义绑定，不运行选择谓词或消耗旧查询 cursor。迟到事实不增加
  输出成员。源 Get 在锁外，整次 selected 验证的取证、当前 Hold、内部读自审计和最终
  计划/owner 复核共享一次既有服务 deadline。不可用/缺失/损坏证据、Schema 漂移或读
  自审计失败保留原计划，等待合法过期接管重查或所有者取消，不另选一批替代输出。
- 当前 Hold 仍以 ADR-0021/0022 的认证判定检查原查询的当前证据（可包含迟到事实），
  不是仅看固定输出成员。匹配时失败、写 export.blocked 并清合法活跃计划；不改变原
  输出成员。生成后仍走原 sealed finalizer，最新 Hold 集绑定终态 CAS；详情/下载门禁
  不变，认证/Hold/自审计通过前不输出明文。
- Put 前复核原计划、最新 Schema 定义和当前未过期 owner；Put 成功后按有序身份/版本
  核对生成 JSONL，保存 sealed 检查点时再次复核计划与 Schema，**同一次 CAS 消费计划**。
  两种活跃阶段互斥。终态/取消精确匹配已捕获计划与 owner 后清运行元数据，保留原事实
  和 WORM；未知或错绑计划不自动清理。retry 仍创建新任务，不继承原计划。
- 取消/过期不撤销远端 Put。崩溃在 Put 后、sealed 保存前时，若 selected 已提交，新
  owner 可以按已知成员生成新的 attempt 对象；旧 Put 结果未知，不能发布/删除它，
  不盲重放旧 key 或宣称只写一次。旧 owner 的晚 Save/终态不能消费替代 owner 的计划。
  明确 Put 错误仍沿用原失败终态语义，不是无限自动重试策略。

## 部署、成本与验收

无新 REST 路径/scope/公开字段、topic、gRPC 方法、SQL 表或密封格式。API/worker 与
所有 control writer 须配套停写升级；旧版本即使支持 sealed 检查点也可能丢掉计划或把
它失败清理，不能混跑。备份保留整个 control（任务/关联/leases/plans/checkpoints）、
原 ledger/hot/journal/确认/密钥；回滚须核对字段保存能力及未知远端结果。文件仍单写者，
沿用 descriptor-relative 私有文件策略，不改原 ledger、留存或 COMPLIANCE。

计划最多增加两个有界活跃成员文档，但共享 control 的克隆/签名/CAS、初次历史扫描与
当前 Hold 扫描成本仍在；旧 PG v1 仍物化旧快照。没有恒定内存、大文件容量、强杀 I/O、
严格跨副本公平或生产吞吐承诺。新 Key ID、多版本历史密码学/对象 Hold 与业务执行协议
仍是独立待办，不以本决策授予合规或发布批准。

回归在真实 Save/append/Put/Get 边界覆盖未知结果、文件重启超过 cursor TTL、迟到事件、
内容/Schema/坐标/MAC/顺序/预算污染、当前 Hold、读自审计、deadline、取消/续期/换主、
阶段消费与终态不回退；独立 PG17 pools 验证共享 CAS/预算/tenant delta。原有 post-Put
和 heartbeat 回归按真实 selected/sealed 边界校准，不降阈值/删断言或将旧阶段重新计功。
完整 quality/Web/security-scan 分别保留原始结果，安全扫描失败继续阻塞发布。
