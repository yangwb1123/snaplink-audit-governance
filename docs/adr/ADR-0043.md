# ADR-0043: 既有恢复详情的控制面读取与单次预算

状态：Accepted  
日期：2026-10-18  
关联：ADR-0013、ADR-0016、ADR-0019、ADR-0033、ADR-0035、ADR-0038

## 背景与有限范围

GetRestore 只返回申请/决定元数据，却走通用 Store.Read，物化所有租户 hot/cold 历史。
文件读取的分配工作随无关证据增长；PG v2 的无关证据表锁/坏冷记录也能阻塞或拒绝
该观察，占用原 Store 读锁/操作预算。Load 返回有效快照但同时取消/耗尽预算时，原
实现还可能返回捕获值。这不是必要的事件认证或恢复回放，不能混淆为读事实要求。

本决策只改既有恢复详情，不扩产品能力。可归因的物化/依赖修复不证明旧 service
累计10m超时/原导出 running 的唯一根因；旧0014自验/独立失败及同源码收尾通过
均保留。审批不是执行，元数据可观察也不证明原证据健康或未知写操作未曾提交。

## 决策

1. GetRestore 显式使用现有 ReadControl，v2不物化租户 hot/cold、不查询证据表或
   Get/Put WORM。每次调用读取当前control，不缓存旧决定，也不将捕获值Save回去。
   只返回原同tenant记录，缺失/其他租户仍404；原字段、历史/未知状态和时间不推断
   或升级，不新增当前tenant注册检查、ID修复或全租户详情例外。
2. 一次 Store.WithOperation 覆盖原读取和捕获后context检查，ReadControl及v1回退
   继承它，不重启deadline或重试Load。取消前不Load；底层错误、超时或捕获后取消
   返回零RestoreRun，保留原错误/一次deadline分类。独占副本含独立时间指针。
3. 不Save、不新增事实，保留原恢复元数据静默读策略；不借此削弱回放、事件/回执
   等必要读自审计或认证。原HTTP权限、tenant选择、错误包和缓存行为不变；完整
   M1权限/回执/恢复矩阵及其他缓存/深链边界仍未完成。
4. 不改变创建/审批、原回放与提交的分离预算、证据/业务版本绑定或业务执行协议。
   当前Hold、owner/阶段fencing、终态不回退、共享队列128/32与running2/tenant1
   继续独立权威；元数据不是下载授权、执行回执、完整性或自动重发未知写的依据。

## 验证与限制

- 新回归先在原生产源码复现：真实文件相同control、1→32个额外hot事件的同一详情
  读取出现随证据增长的分配；保留原真实归档源/Put/fsync，额外hot样本仍逐次真实
  Ingest/Save/append/fsync及重启，不改TMPDIR或将文件测试内存化。此为分配工作
  对照，不是整包wall、吞吐、磁盘唯一归因或容量SLO。
- PG17独立pools实际锁住两张证据表，确认全局Snapshot确实耗尽调用方原短预算，
  详情却可读且能观察另一pool新提交的决定；只增加那次决定的版本/事实，不覆盖
  原完整证据/control。另持久损坏本轮无关冷记录，详情仍可读，而目标回执仍失败；
  真正control Load失败必须零对象，不能用缓存/猜修复隐藏故障。
- 实际Load边界覆盖成功、原错误、预取消、带快照的迟取消/超时、较早caller预算，
  零Save/append/WORM；真实两租户文件、selected计划/当前Hold、批准/拒绝、未知
  control temp、字节/inode/完整事实与重启另验。临时文件不删除/截断或猜成功。
- v1仍物化旧快照，共享control历史/克隆、其余全历史/锁内成本和CreateTenant/
  通用Update尚未整体改造。无新字段/路径/scope、SQL/迁移、topic、Proto方法或
  持久/密封格式；沿用完整备份、文件单写者/PG共享与停写升级回滚，不清历史、
  WORM/旧卷，不缩短COMPLIANCE，不执行业务恢复。
- 专项/PG、全service逐测试/原导出阶段、完整quality/Web/security和随后独立验收
  分别绑定源码留证。局部修复/一次绿不证明历史running或长期稳定性闭环，M3仍
  Partial，M4/M5协议、整栈/Hosted Login/容量/容灾/正式合规独立待办。安全扫描
  非零仍阻塞发布，不修改规则/阈值或自授豁免。
