# ADR-0026: Console 事件页与 facets 的锁外认证读取

状态：Accepted  
日期：2026-10-17  
关联：ADR-0002、ADR-0013、ADR-0015、ADR-0019、ADR-0025

## 范围与背景

两个 Console 兼容查询经 consoleEvents 在 Store.Read 闭包内回读 WORM，慢 Get 会阻塞
同 Store 的租约续期、所有者取消和其他控制写。原热正文可以在内容认证前参与筛选，
归档链哈希也不能替代重建内容认证；派生搜索 sidecar 本身不受 SourceDigest 认证。

只改 QueryConsoleEvents / QueryEventFacets 及其既有两个 HTTP 端点，不改普通事件
固定成员查询、旧全量时间线/summary/replay 或跨租户单事件兼容 helper。不新增查询
参数、持久模型、迁移、scope、ClickHouse 接线或业务执行，不重复交付导出进度。
后续 ADR-0027 单独改造 operation summary 的认证源/锁外读取与共享 deadline；旧全量/
replay/restore 不因此完成，本 ADR 的 Console 语义不变。ADR-0028 后续仅改造
operation replay（包括已有内部恢复委托的原证据读取）；旧全量/aggregate replay
及恢复整体流程仍未完成，不改变本 ADR 当时的有限范围。

## 决策

1. 每个服务调用用 Store.WithOperation 建立一次原有 deadline，Store.Snapshot 捕获
   独立深副本。只有捕获/后端物化持 Store.mu；远端 Get、精确 Schema/内容/链认证、
   筛选、排序/聚合及一次失败关闭读自审计均在其后共享同一预算，不按对象或 append
   重新开始。取消和 store_timeout/503 分类与计数、原生产 timeout 均不变。
2. 从 committed receipts 锚定成员，验证 map key 与 receipt tenant/event 正文绑定。
   scoped 读取同时检查本租户 key 与正文，错绑不能被其他租户声明隐藏；其他租户
   完整证据不 Get 或认证。已授权 all-tenant 读取检查所有 committed receipts，不
   静默跳过其中的坏证据。没有 receipt 的热正文/journal 在 v1/v2 都不是查询事实。
3. 所有事件谓词之前，以原热正文或 archived receipt 指向的 WORM 验证精确身份、
   链坐标、精确 Schema 身份/版本、重建内容与链哈希。不能因损坏的时间、actor、
   source、type、outcome 等谓词变成正常空结果。缺失精确 Schema 不取最新版本替代；
   停用历史 Schema 不妨碍精确版本认证。坏/缺 committed 证据拒绝整次读取，不返回
   部分页/统计或追加成功读事实。捕获目录是一次读取观察点，不是跨后端原子快照。
4. 服务层已有 payload_field/digest 条件复用认证原值匹配：仅 Schema 声明 searchable
   且存在的字段，按条件自身 bound/legacy 格式推导，保持加密字段和大整数精度。
   不信任保存 sidecar 的存在、格式或值；不会把内部重建的明文替换进响应事件。
   Console HTTP 仍只接受原有筛选白名单，不新增敏感条件 URL；事件响应递归剥离
   搜索摘要，副本由调用方独占，不能污染原证据。
5. 保留既有授权：签名 tenant claim 权威；平台与专门允许的 tenantless Console 可
   省略 tenant_id 作 all-tenant 读取，显式合法筛选只收窄。普通租户不能借查询参数
   跨租户，其他 scoped API 不获得此例外。服务层 optional scope 不是新增授权依据。
6. 保留兼容 live 语义：事件按 occurred_at/sequence/event_id 降序，原 cursor 线面
   不变；**Console count 是本次 cursor 之后的匹配数**，首页为全部匹配数，续页可
   因迟到/新提交而变化。它不同于普通固定成员事件查询，也不同于分页时间线的总
   count。facets 忽略分页输入，total/分类统计基于全部筛选匹配；clients 取可信
   source_system，providers 没有可信对应字段，继续为空。空结果保持空数组/空 map，
   不改成 404；不声明固定成员、全历史完整性或投影完整性。
7. actor-bearing 成功（包括空结果）append-before-serve 恰好一个 audit.event.read，
   保留原 query target、scope/actor 和 snaplink-console 或 facets detail。内部空
   actor 保持零事实。捕获/Get/认证/游标/追加失败或取消返回零结果；append 已持久但
   回报未知仍拒绝输出，不撤销尝试事实，不视为字节交付或业务执行证明。只追加独立
   事实，不把捕获快照写回覆盖并发终态、租约、Hold、计划、页或检查点。
8. 两个 HTTP 端点在认证前设置 Cache-Control: no-store，覆盖成功和全部错误。
   认证失败保持固定脱敏错误，不输出原载荷、密文、搜索摘要、Token 或后端诊断。

## 后续复用

ADR-0030 后续让普通固定成员查询的 reference 初次选择复用本认证扫描，并仅为普通
查询传入原 10000 匹配上限；Console 仍传零保持原无限制语义与 live/count/facets 口径。
不重复交付本 ADR 的 Console 能力，也不把共用扫描称为消除历史物化/认证成本。

## 成本、兼容与未交付项

无新公开字段、路径/scope、topic、Proto 方法、SQL/密封格式或持久运行元数据，无需
迁移。认证收紧会拒绝以前可能被过滤隐藏的坏正文、错绑回执或不可认证精确目录；须
修复原证据/目录，不能删历史、改身份/版本或降低认证换成功。

仍物化历史并认证扫描作用域内的 committed 证据；limit 不是源扫描、字节或内存上限。
未交付 ClickHouse facets/统计、生产容量 SLA、全租户完整性、参考初页/其余 Hold 成本
或旧读链路整体改造。当前 Hold、共享队列 128/32、running 2/1、lease fencing、终态
不回退和 selected/generating/sealed 含义均不变；M3 整体仍 Partial。

## 验证与部署

先在实际暂停 Get 边界复现原 mutex 阻塞，再验证 scoped/all-tenant 锁外控制写、热冷
谓词/receipt/Schema 污染、缺失证据、bound/legacy 敏感条件与大整数、空结果/live 计数、
捕获目录/返回值独占、Get/append deadline、取消、追加失败与未知结果。短预算回归
预先读取精确夹具字节，实际 Get/append 才等待 deadline，不给文件准备施加性能要求。
纯认证/条件/预算矩阵使用隔离内存对象的真实 Put/Get 和控制面 Save/append 边界，避免
无关文件准备 fsync 堆积；四个文件 Get/控制锁回归、HTTP 与 PG 组件仍使用真实 FileStore。
没有减少用例/断言、改变生产超时或扩大测试 timeout；内存对象夹具不证明崩溃持久性。
工程失败又暴露通用文件夹具重复初始化与 HTTP 批次上界对文件吞吐的隐含要求：只对
新建测试域，把同样三个真实管理 API 产生的配置/三条事实从隔离准备区合入一次目标
Save，逐字段合并并回归完整逻辑等价/保留其他 control；不是旧全量快照回写。业务测试
仍用原文件 Store，故障/CAS 夹具继续逐个 API 提交。500/501 上界测试保持全部成员、
体积/状态断言，使用健康内存依赖跑真实 HTTP/ingest/Save，分别核对 accepted 兼容响应
和持久 committed receipt；另在真实 Save 等待原默认 deadline，必须 503/store_timeout，
超上界则零 Save。不把 count 准入、accepted 响应或测试准备性能当提交/吞吐保证。
HTTP 验证授权先于 Get、no-store、摘要剥离与固定错误；独立 PG17 pools 在 Get 暂停时
执行同 Store 续期、另一 pool 取消/改 Hold 和策略，读取不得覆盖其已提交终态/control。

完整 quality、Web 和 security-scan 各自保留命令与真实退出码；组件回归/模型自验不是
外部独立工程验收、整栈、容量/容灾、正式合规或发布批准。安全扫描非零继续阻塞发布。
沿用现有数据/密钥备份、停写升级与回滚核对，不清 WORM、历史、未知远端结果或旧卷。
