# ADR-0032: 按坐标读取的回执身份与精确 Schema 正文绑定

状态：Accepted  
日期：2026-10-17  
关联：ADR-0002、ADR-0013、ADR-0019、ADR-0026、ADR-0030

## 范围与背景

普通 reference 初次选择已经在所有谓词之前认证 receipt/map、精确 Schema、内容和链。
单事件 GetEvent、固定成员续页及 ClickHouse 候选的实际输出页共用 readQueryEvidence，
却只在给出 StreamID 时比较链坐标，没有将请求 tenant/event 与 receipt 正文再次绑定。
旧兼容快照中，一份内容/链有效的其他事件与其 receipt 可以共同放在错误 lookup key 下；
归档路径还可能在拒绝错绑前读取其他身份的对象。版本化 Schema map key 也不能证明其
正文 tenant/id/version 正确，原内容重建可以使用正文身份已经漂移但字段声明相同的目录。

本切片只收紧上述按坐标读取，复用共用 resolver 的精确 Schema 检查，不重选固定成员，
不改 ClickHouse 候选来源/失败策略，不重交初页认证、锁外 Get 或任何导出续跑阶段。
旧跨租户单事件兼容 helper 没有改造或新增生产调用；HTTP 仍须显式单租户 scope。

## 决策

1. readQueryEvidence 在持有 tenant read view 时，先核对 receipt.TenantID/EventID 与
   本次可信 tenant 和所请求 reference.EventID 精确相等，再核对原已给出的链坐标。
   即使单事件未给出 StreamID，也必须做身份绑定。错绑返回固定 conflict，零源 Get、
   零成功读事实/输出；不能仅凭 map key、另一有效正文/链或投影候选推断身份。
2. 锁内只捕获自有 receipt/hot/catalog；源 Get、密码学与内容重建继续锁外。共用
   resolveQueryEvidence 对热或 WORM 正文按其精确 Schema key 取定义，并核对 Schema
   正文 tenant/id/version，缺失或错绑返回固定 conflict。随后保留原 receipt/正文身份、
   内容摘要和链认证。缺失历史版本不取最新版本替代；停用的精确历史定义仍可读取。
   不将内部重建的明文替换响应保护字段，也不把派生 search sidecar 当作证据身份。
3. 固定成员续页仅取本页原坐标，不重新选择、扫描已服务前缀或重问投影；原 count、
   顺序、HMAC scope/source/subject/filter/page-size、15 分钟 TTL、10000/4 MiB/tenant16
   预算不变。ClickHouse 实际输出页同样核对精确 Schema；候选全量 receipt 复核、故障
   不降级、敏感条件强制 ledger 的策略不变，不声称新验收了真实 ClickHouse 容量。
4. 取证循环/源 Get 后检查原 context，保留一次 Store.WithOperation 覆盖 capture、
   Get/认证、结果和一次失败关闭读自审计；不逐对象或 append 重启 deadline。GetEvent
   在 audit append 返回成功后也检查原 context，取消/超时仍返回零事件。已耐久但结果
   未知或随后取消的尝试事实不撤销，不作为字节交付证明；内部空 actor 零读事实保持。
5. 返回副本和捕获目录仍独占；本次取证使用捕获的精确定义，后来的目录漂移由下一次
   请求观察，不混入进行中的认证。只追加独立 trail，不回写旧快照覆盖并发终态、lease、
   Hold、策略、计划/页/检查点。捕获观察点不承诺跨后端原子快照、完整性或业务版本绑定。
6. 现有 canonical/compat 单事件 HTTP 和 GET/POST 查询保持原权限、签名 tenant 权威、
   平台显式选择与 no-store；compat 详情不获得 Console all-tenant 例外。错误只含固定
   安全分类，HTTP 递归剥离搜索摘要，不新增 URL、载荷/密文/摘要/凭据日志或持久化。

## 兼容、成本与未交付项

无新路径、scope、公开字段、topic、Proto 方法、持久模型、SQL 或密封格式，无需迁移。
缺失/错绑的精确目录和 receipt 正文现在明确失败关闭；修复原证据/目录，不能改身份、
伪造 receipt、重签历史、删账本/WORM 或降低认证换成功。reference 初次选择等既有使用
共用 resolver 的路径继承前置精确目录核对，不重算为新交付。

仍有 control/catalog 克隆与旧 v1 历史物化成本；本页按坐标读取不等于其余历史扫描、
旧跨租户 helper、ClickHouse facets/完整性、生产容量或恒定内存已经解决。M1 完整语义
矩阵、M2 其余成本、M3 最终整块合并/密封及认证流式下载/其余准入、M4/M5/恢复执行
仍未完成。当前 Hold、读自审计、共享 128/32、2/1 预算、owner/阶段 fencing、终态不回退
及 selected/generating/sealed 的含义完全不变，M3 整体仍 Partial。

## 验证与部署

新回归先确定性复现热/归档的精确 Schema 正文漂移被 GetEvent/原续页/投影实际页接受、
错误 lookup key 下另一真实事件/receipt 被读取，以及 audit 已耐久后取消仍输出事件。
随后覆盖精确历史停用版本/保护大整数/owned 输出、本页一条源 Get、捕获目录并发变化、
同一次 Get/append deadline、真实超时计数一次、追加失败/未知/取消零结果。纯认证矩阵
沿用实际内存 Store/Put/Get/append，不作为文件耐久性证明；真实文件重启保存原成员集与
目录故障，修复自有夹具后仍只读原下一页，原 cold receipts 不变。独立 PG17 pools 验证
持久目录故障可见、同 Store 续期/另一 pool 取消与当前 Hold/策略/目录不被旧捕获覆盖，
晚 owner 不发布。HTTP 覆盖授权先于 Get、no-store、固定安全错误与摘要剥离。

完整 quality/Web/security-scan 和组件回归分别留真实命令/退出码/源码绑定；自验不代替
随后独立工程、整栈/Hosted Login、容量/容灾、正式合规或安全发布批准。安全扫描非零
继续阻塞发布。沿用原完整备份、停写升级/回滚与旧 writer 字段保存要求，不清未知对象、
账本/journal/WORM/历史或旧卷，不缩短 COMPLIANCE，不产生业务执行副作用。
