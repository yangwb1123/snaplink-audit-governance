# ADR-0019: 导出运行租约、心跳与过期执行 fencing

状态：Accepted  
日期：2026-10-14  
关联：ADR-0010、ADR-0014、ADR-0017；仅补充租约/心跳，不交付检查点续跑

后续：ADR-0020 补充所有者取消、关联新任务重试及公共安全失败类别；本 ADR 的
“不支持”清单是批次 11 当时边界。ADR-0021 后续允许合法密封检查点在 running
原 lease 到期后以新 owner 续跑终态提交，不失败或重新排队该任务；逐页/逐块生成
续跑和分块认证下载仍未交付。ADR-0023 后续另增加生成前 selected 固定成员计划，
只有合法到期计划才可跳过选择继续整块生成；心跳不是该计划，逐块字节进度仍未交付。

## 背景

ADR-0014 的共享 running 预算限制正常领取，但崩溃运行只能依靠 24 小时年龄恢复。
长时间健康作业也可能被年龄恢复误伤；过期执行的迟到 Put/终态写必须与控制面所有权
区分。归档调用取消并不保证远端未提交，不能把超时当作 WORM 回滚。

## 决策

1. 私有 control 增加 `export_leases`，每项格式版本 1，绑定 job/tenant，包含随机
   owner、heartbeat_at、expires_at。领取在同一共享 control CAS 内检查既有全局 2 /
   租户 1 running 预算，同时保存 running、真实 StartedAt 和租约。租约不进入
   公共 ExportJob/列表/摘要、租户 hot 文档、载荷、自审计详情或诊断日志；没有新增
   REST scope/接口或 SQL 表。文件控制文档及 PostgreSQL v1/v2 保存均须保留此元数据。
2. 租约固定 2 分钟，执行器每 30 秒在 control-only CAS 内续期。续期须精确匹配
   owner/job/tenant、running/unfinished、版本及时间顺序，且当前租约尚未过期。
   续期保存失败、丢失所有权、取消或时钟后退导致时间不合法时取消执行上下文；不能
   复活已过期租约。owner 来自 crypto/rand，不把非安全 CAS jitter 当作所有权标识。
   每个有限执行器至多一个 heartbeat goroutine，结束后停止并等待它退出。
3. API 启动和每秒队列 pass 在派发前收敛过期租约；worker 原 RecoverStuckExports
   同样识别租约。到期边界为 now >= expires_at，恢复在同一 CAS 中失败作业、清空
   对象路径/摘要/事件数、删除租约并追加一个 `export.recovered`，详情固定
   `lease_expired status=failed`。无变更零保存；失败/未知保存不返回成功计数，错误
   不返回部分恢复结果。畸形或错绑的相关租约失败关闭，不从 job 内容推断所有权。
4. 仅缺少租约的旧 running 使用原年龄恢复：有效 StartedAt 优先，否则 CreatedAt，
   默认 24 小时，仍要求严格早于阈值。健康有租约的任务不按旧年龄判死；排队年龄
   不是心跳。终态不退回 pending，不自动重跑同一任务，不宣称恢复成功执行了导出。
5. 执行上下文携带私有 claim。终态 CAS 只接受该 claim 的精确、未过期当前租约，
   删除租约与终态/失败自审计同一次保存。无 claim、错 owner/tenant、过期或已恢复
   是无写入；保留有界终态保存重试。control checked 回调前后检查同一 operation
   deadline 的取消状态；这不能撤销已经进入持久化边界的外部提交。
6. 在 Put 前检查所有权，Put timeout 继承执行取消。对象 key 使用 job 与随机 owner
   的不透明哈希派生，不公开 owner 本身；不同 claim 不竞争同一对象身份。租约失效
   或恢复后，迟到 Put 可能留下无引用的 sealed WORM 对象，但旧执行不能发布路径、
   覆盖终态或删除对象。Legal Hold 选择/下载门禁、自审计、tenant/job AEAD 和摘要
   认证保持权威；认证前不输出明文，不降低 COMPLIANCE 或变更事实源。

## 支持与验收边界

- 共享预算/所有权仅限同一个 control CAS；文件账本仍单写者。到期 fencing 控制的是
  当前持久 claim，不是跨主机强杀能力：失联进程或忽略取消的远端调用可能仍执行，
  不能承诺实际物理 I/O/goroutine 始终不超过 running 预算。
- 使用各进程 UTC 壁钟，须运维同步时间；没有分布式时钟/严格公平 SLA。时钟前跳
  可以提前失效，后退可导致执行取消。畸形元数据会阻断相关恢复/派发，不能清空它
  换成功，须停写核对原 control 与运行记录。
- 心跳不作进度、检查点或证据完整性证明。仍整块历史选择、JSONL+AEAD 密封；无
  检查点续跑、关联新任务重试、受控取消、结构化公共失败类型或分块认证下载。
  old pending/终态 DTO 不变，已有 sealed 对象仍按原下载认证。
- 回归覆盖真实 Store Save、归档 Put 和 control CAS 边界：克隆/重启保存、只改
  control、取消不保存、错绑/过期拒绝、续期失败取消、恢复计数/CAS 冲突、终态事实
  一次性、健康慢 Put 与忽略取消的迟到外部提交。独立 PostgreSQL 17 连接池的三轮
  race 覆盖同作业竞争、共享全局/tenant 准入、跨实例续期和到期 fencing；不是负载、
  容灾、完整 Compose 或正式 WORM 验收。完整 quality/security 结果独立记录。

## 部署、备份与回滚

- 不混跑旧/新 API 与 worker 导出执行器：旧二进制忽略租约且不执行 owner fencing。
  升级前停止新领取、停写并核对/排空旧执行；保留 pending/终态和既有证据。不能仅
  因观察到 running=0 就认定远端 Put 已结束。API/worker 继续使用相同数据库、密钥、
  归档和服务身份；配置一致性键不证明二进制支持租约。
- control 备份必须连同私有租约元数据，与 ledger/hot/journal、发布确认和密钥按既有
  流程保存。心跳增加活跃 control CAS 写，终态历史成本不受队列预算限制；生产需
  测量数据库冲突、写放大、时钟偏差及归档延迟。
- 回滚前停止所有新版本领取/执行，完成或核对过期恢复及远端未知结果；不得由旧版本
  接管活跃租约、人工改 owner/续期、将终态退回 pending、删除无引用 WORM 对象、
  清空租约或通过缩短保留期换启动/容量成功。
